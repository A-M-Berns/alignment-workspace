Everything below was done on a copy at `workflow-2026-10-02/artifacts/review-copy/`; the prototype itself was not touched. Scratch copies for the refusal trials lived in the session scratchpad. Every event I wrote is marked `SIMULATED` in its `gloss`; no human answered anything.

**What I did, in order.** (1) Ran the checker as the README says. (2) Read `graph/tasks.md`; the top ranked unit was `gestalt instrumental-convergence (M, ~2 min)`. (3) Added `@reviewer` to `handles:` and `users:` in `policy.yaml`, invented a plausible answer and wrote the one gestalt event into `graph/events/reviewer.jsonl`, logged a `confusion` line in `DESIGN-LOG.md`, reran. (4) Filed a picture against `a2-monotone-in-resources` (a bounded or satisficing objective, under which more resources do not raise attainment), which per §2 turns the leaf into a `cases` node: three new node files, two rows, four judgment events. Reran. (5) Tried nine things the checker should refuse. (6) Ran the shipped tests.

## What worked

- The plain run passes on the fixture in 11 s and 63 MB, prints one `WARN` and one `OK` line, and regenerates the four derived files. `--help`, `--why`, `--as @handle`, `--scope`, `--dry-run` all run; `--as` with an unmapped handle is refused cleanly (`REFUSE 5 --as`).
- The ten-minute session was writable from the documents alone: the README's steps 2–4 and §5's event-line paragraph were enough to produce a handle entry, a users entry and a gestalt event that the checker counted on the first try. The digest said `events counted since the previous derivation: 1`, the gestalt unit left the list, and the root's `gestalt` appeared in `derived.json` at J 8 (I gave a reason).
- The `DESIGN-LOG.md` line format in the file's own header was enough to write a well-formed `confusion` entry (no `WARN` about it).
- Refusals are precise and name the file and line. All three mandated trials refused as the documents promise: a typed `level: 8` in a node file → `REFUSE 4 ... node file carries the key 'level'`; an `estimate` by the AI handle → `REFUSE 5 ... an AI handle writes no judgment`; a hand edit of `tasks.md` → `REFUSE 7 ... generated_hash does not match`. Six extra trials also refused correctly: a weight judged on the residual row (10), a Statement edited without a version bump (4), an evaluative word in a Statement (3), a class tag naming no class (10), a duplicate event id across ledgers (1), an event kind the checker does not know (2).
- `withdraw` of my own gestalt event worked as §5 says, and the gestalt unit came back.
- The picture filing, once the enumeration limit was lifted in a diagnostic copy (see below), did what §4 promises: a J 8 conditional of [0.1, 0.3] on an admitted row conceded `a2`, `a2` showed `conceded by pic-B-bounded-objective` with a revival cost of 30 min, and the `probabilistic` preset on `instrumental-convergence` conceded the root (`loss 19/25 > 1/2`). A human author's picture was admitted at filing without an `admit` event, as §5 says.

## Where the documents and the code disagree

1. **The enumeration limit.** The checker refuses when the joint world model exceeds 2^15 worlds (`MAX_WORLDS`), printing `REFUSE L graph/: 122880 worlds exceed the enumeration limit 32768`. Neither the README nor PROTOCOL mentions a limit, a rule `L`, or a refusal with no file behind it. The untouched fixture sits at 30 720 of 32 768 worlds (23 variables), so **any** new picture is refused: my two-row table (×4) gave 122 880; one extra row on the existing `a1` table gave 40 960. `--scope` does not help, because the world model is built over every root before scoping. A newcomer following the README cannot file a single attack anywhere in the shipped tree.
2. **Task kinds that are not event kinds.** §5 lists `re-examine` and §6 `reconcile` among task kinds, and §5 says an event's `kind` "is a task kind below or ...". The checker's `EVENT_KINDS` has neither: an event of kind `re-examine` is `REFUSE 2 unknown event kind`. `audit` is accepted as an event kind but belongs to neither `LEVEL_KINDS` nor `JUDGMENT_KINDS`, so how an audit's outcome is recorded, and what it does, is undefined by the code.
3. **`versions.json` is not protected.** §1's table and prose say `versions.json` is "regenerated by the checker, never edited" and that "a generated file edited by hand is refused". It carries no `generated_hash`; my hand edit passed with `OK`.
4. **The gestalt unit.** §4: a root "with no judgment anywhere" gets the gestalt task first. Code: every non-plan root without a gestalt gets it, permanently, with the `--why` text "root outside both terms until judged", although `instrumental-convergence` already had a derived probability (0.46) from eight judgments on its leaves and its settled truth already counted in H(S).
5. **Normalized text.** §2 says punctuation is removed before comparing Statements. `normalize_statement` strips Markdown markers and hyphens only; a changed comma or apostrophe demands a version bump.
6. **Event fields.** §5 says a gestalt carries `derived`; the checker never looks at it (a gestalt without it passes). `verbatim` is checked only when `question`/`answer` are present. The fixture's `external` event uses a `ref` field the protocol does not list. The trace field `installment: {done, of}` that drives the "6–8 (2/3)" display, the `or`-node field `tag` that suppresses a `classify` unit, and the node reference `supersedes` are all read by the code and absent from §2 and §5.
7. **Policy keys.** §1's `policy.yaml` row omits `maintainer` (required: `rule` and `survey` events are refused without it), `illustrative` on handles, and `reask_days` / `time_tested_years`, which the fixture carries and nothing reads.
8. **Anchor 14 and the attribution flag.** §3 says levels 10 and above need a logger other than the author; the code mints anchor 14 from any `external` event, the author's or an AI handle's included (only the kind is checked). An `external` or `admit` event on a node silently clears the *attribution unvetted* flag; the documents never say what clears it.
9. **A conceded plan as leading candidate.** The commit line reads "no plan vetted enough to commit to; leading candidate deference-toward-bounded-agents" while that plan is `conceded`. §6 never says a conceded plan stays an option in the act. Because the outside option's utility is `null`, it is valued 0 as a point and [−1, 1] as an interval, so every plan's value interval prints as [−1, 1].
10. **Generated files depend on flags.** The committed `tasks.md` and `view.md` were rendered with numbers on; the README's plain run rewrote both (no `## Why`, no `cost` column: a 170-line diff) before I had done anything. `--scope` leaves a scoped `tasks.md` behind. The hash check cannot see any of this; the first pull request carries the noise.
11. **The digest misses root flips.** `statuses flipped` compares node statuses only; `instrumental-convergence` going `open → conceded` through its preset budget was not reported, only `a2`.
12. **Safety margin on the wrong roots.** The view prints `safety margin: None` for the `probabilistic` root; §4 says only an open `worst-case` root shows one.
13. **Shipped tests.** `--self-test` passes; `python3 -m unittest tests.test_graph` fails 1 of 32 on the untouched fixture: `test_instrumental_convergence_cluster` does `json.loads` on `--dry-run` stdout, which carries the `WARN` and `OK` lines after the JSON (`Extra data: line 2705`). The README's "It must print `OK`" is also literally false: the first line is a `WARN`.
14. **A leaf that becomes a table.** The leaf's earlier range judgment (`e-030`, [1, 1]) stays `counted`, is listed in `derived.judgments`, and is ignored by the world model (a `cases` node's probability is Σ w·p). No flag, no `stale`, no mention in §2 or §5.
15. **`--dry-run`.** README and §1 present it as "derive to stdout, write nothing"; it prints the whole `derived.json` (2 700 lines) plus the log lines, not a task list, so it is not the safe look at the tasks a newcomer wants.

## The three most confusing moments

1. **The refusal with nothing to fix.** Filing one picture, exactly as §2 describes, produced `REFUSE L graph/` with no file, no rule I could look up, and a count that no document had warned me about; the tree was already at 94 % of the limit before I arrived, so a one-row addition to an existing table refuses too. A contributor's first attack cannot land.
2. **The gestalt that bought nothing visible.** The top task asked for a holistic probability on a root that already showed a derived 0.46 from eight judgments. My stated [0.55, 0.8] displayed as [7/40, 1] = [0.175, 1], because the root is at V 2 and the width floor there is 1. When I withdrew it, the unit returned to position 1. I could not tell what the two minutes were for.
3. **The ground moving under the first run.** Before I did anything, the plain run rewrote 170 committed lines; after my first event, the audit task changed from `e-012` to `e-007` (the audit is seeded by the set of counted ids, so every new event re-rolls it); and the commit line told me the leading candidate was a plan the view marks conceded.

## The three changes I would make first

1. **Make the world model scale, then tell the user.** Enumerate per connected component of shared leaves (or per root, joining only over shared variables) instead of one joint product over every root; failing that, raise the limit with the time and memory cost stated (122 880 worlds took 47 s and 205 MB on a copy with the limit lifted) and refuse with a numbered rule naming the root and the count. Until this is done, write in README and §2 that no new table or row can be filed in the fixture.
2. **Make the generated files flag-independent and the logs separable.** Render `tasks.md` and `view.md` the same way regardless of `--why`, `--as`, `--scope` (per-user renders to stdout or an uncommitted path), send `WARN`/`OK` to stderr so `--dry-run` is parseable (this also fixes the failing test), hash `versions.json`, and make the digest report root-status flips.
3. **Close the vocabulary gaps in PROTOCOL.** A table of refusal rules 1–12 and `L`; the event-id convention; the full event field list including `derived`, `ref`, `installment`, `attested_by` and which are checked; a rule for judgments on a leaf that becomes a table (mark them `stale`, or carry the range into the residual row's conditional); and either drop the gestalt unit for roots that already have a derived probability or list it unranked as "no gestalt yet".
