## 2. Blocking issues

None. What I tried to break, and why each attempt failed, is in §4; the candidates I weighed and rejected:

- **"`witness_package_paperDP` is N+ but really N−."** The witness market is FAF's actual LIA over `paperDP 𝗜𝚺₁` with consistent worlds at every stage (`paperDP_hworld`); the re-pricing moves infinitely many day-`0` sentences (`overlay_ne_lia`, proved from the market maker's finite table, not assumed); an e.c. trader is rewritten non-trivially (`familyReader_splice_ne`); and the overlay's inductor-hood is the criterion-level theorem instantiated, not a class result. My probe `WitnessDayZero.lean` shows the overlay equals the LIA on every day `≥ 1` and that every fired body is price-free; `WitnessOracleConst.lean` shows the oracle's budget polynomial has degree `0`. So the witness is degenerate *with respect to the certificate's new content* (§3 item 1) but it does inhabit the full hypothesis package of `overlay_isLogicalInductor'` non-trivially, and it is exactly the body the mandate prescribed (`some (const (1/2))`). I grade it **N+ for T1, N− for T1.3's new clauses**, and record the second half as a disclosure to add, not as a misgrade — the ledger never claims N+ for the certificate structure (its row is kind `D`, witness `wCertificate`).
- **"The T3 refutation is an artifact of the encoding."** It is a theorem about FAF's traders, whose `letE` sharing lets a cost-`O(n)` feature denote `2^{2^{n+1}}` (`sqTower_denoteWith`, `sellBottom_ec` through FAF's own `ofTradeBlocksBig`/`concatVar`). FAF's `EF` docstring (`Framework/Criterion.lean:86–97`) discloses `var`/`letE` as an extension of the paper's grammar and says it "enlarges `EfficientlyComputable` and strengthens every theorem quantified over it, including `IsLogicalInductor`", citing the paper's footnote (`main.tex:788`: expressible features are "a generalization of arithmetic circuits", "compactly specifiable in polynomial time") as licence. STANDARDS §1 makes FAF's object the object of record, so the refutation is of the target as this run states it. It is not an artifact: probe `ClampSmallOnly.lean` shows it survives the program's own scoping of the clamp to `S_k` (`⊥` is small on every day), and `DegenerateDP.lean` shows the one hypothesis it carries (`hworld`) is genuinely needed. What is missing is the qualifier when the findings speak about the *paper* sources (§3 item 2).
- **"`SpliceCertificate` smuggles the conclusion."** Its three fields are a run-level lookup `exprRun : List ℕ → ℕ → Option (List ℕ)`, `RunAgrees expr exprRun` (agreement with the map on every run `parseRpn` accepts, all spellings), and a `SpliceOracle exprRun` (one `R ∈ FP`, `BlockWF` output, a polynomial output bound, and `R_spec` on every day block and every buffered word). Nothing is quantified over traders or strategies; `EfficientlyComputable (Tr.spliceOn …)` appears only as the conclusion of `EfficientlyComputable.spliceOn`. The chain from the certificate to that conclusion (`spliceStreamRewriter_of_certificate` → `spliceStreamRewriter_of_flatPass` → `unRpn_rpnSpliceRunOn` → `EfficientlyComputable.spliceOn_of_rewriter` → `strategyOfTokens_spliceTokenRunOn_trades`) runs through FAF's `rpnConditionRun`, `unRpn_rpnConditionRun_of`, `runFold_mem_FP`, `strategyOfOutput`, `unaryDay`, `parseRpn` — all FAF's full names, verified by grep. Trap (ii) is respected.
- **"T1 is a squeeze."** The conclusion's content is `noExploit` for every `EfficientlyComputable` trader; the hypotheses are `[IsLogicalInductor Q DP]`, the map `E` (semantic conditions on bodies), the syntactic certificate, and a computable table. The bridge day comes from `bli-found`'s `bridge_lemma` (grade (a), no OPEN in `packages/bli-found/bli-found-open.txt`), the accounting is `Trader.netWorth_difference_le_of_tail_eq` (real: exact cancellation after `N`, two magnitudes before), the transport is FAF's `Exploits.of_boundedDifference` over `v.ConsistentWith (DP.D n)`. No hypothesis is equivalent to the conclusion. Probe `TierB.lean` confirms the one place a squeeze could hide — an `ExprMap` that never fires forces `overlay Q ov = Q`, so T1 at that map is `IsLogicalInductor Q DP` itself — which is the trivial instance the N+ witness is there to exclude.
- **"A core target was skipped."** T1 (with T1.1–T1.5) and T2 are done as the mandate states them; T3 (`stretch`) ends refuted with attempt A's conditional form kept and flagged; T4 is a findings record with the ceiling half refuted, never an OPEN row; T5 (`extension`, "if time remains") is honestly "not attempted".

## 3. Non-blocking issues

1. **The certificate's new content has no instance in the package (disclosure to add; ledger rows `SpliceOracle, SpliceCertificate, RunAgrees`, `EfficientlyComputable.spliceOn`, `witness_isLogicalInductor`, `witness_package_paperDP`).** `wOracle.R_poly = Polynomial.C wOut.length` (probe `WitnessOracleConst.lean`: `natDegree = 0`); `wExprRun b D = some raw → raw = wBody = [1, ⌜1/2⌝]` and `wExprRun b D = none` for `D ≠ 0`; every fired body of `wExpr` has `priceQueries = []` (probe `WitnessDayZero.lean`). So the only `SpliceCertificate` ever built is a day-`0`, constant-body, constant-output oracle — the shape of FAF's freeze `RunOracle` (`R_length_le` constant), which attempt B's `SpliceOracle.ofRunOracle` already observed is a splice oracle. The one clause that distinguishes the package's interface from the freeze (a polynomial, non-constant `R_length_le` for a body that reads same-day small prices) and the `ExprMap.leaves` content ("expressible in the small prices") are exercised by no instance. The ledger's disclosure "map fires on day `0` only" is true but incomplete; it should say: constant body, price-free, degree-`0` budget, no size test in the oracle (the mandate's witness spec had the map fire on every day `k` with the length comparison `a ≥ 4^{sizeBound k}` in the oracle; R-5 discloses that this was left to `bli-assemble`). The fidelity auditor's `WitnessConstantOutput.lean` makes the same point. Fix I'd accept: the sentence above in the four rows and in the report's T1.5 paragraph, and — for a continuation or `bli-assemble` — one instance with a price-reading body (e.g. `add (price ⊥ k) (const (1/2))` on a family atom, `⊥` being small on every day) and an oracle whose output length grows with the run.

2. **The T3 refutation is model-relative, and the findings' severity sentences about the paper sources do not say so (findings R-1 headline, R-2, KI-4; report § The disagreement).** The proved statement is about FAF's `def:ec` with `letE` sharing. Under a literal tree reading of the paper's grammar (`main.tex:786–788` without the footnote) an e.c. coefficient of polynomial size with polynomial-bit constants denotes at most `2^{poly(n)}`, the settlement residual `∑_n 2^{p(n)} 2^{-2^n}` is summable, and the clamp question is *open* there, not refuted. R-2 does disclose the mechanism ("`letE` sharing lets…; without sharing the bound would be `M^{cost}`"), and for `bli-program` §3.2(d)/§4 L5 the refutation needs no qualifier (the program is stated over FAF and itself writes `ε_k` by `letE`-squaring — the same sharing that defeats it). But KI-4's "the clamped reading of 033 is false" and R-1's "T3 is false" are read against bli-paper-033/039 and bli-slides-006/008, whose model is the paper's, and there the honest severity is "the rate `2^{-2^n}` is insufficient under the circuit reading FAF adopts and the paper's footnote licenses; under the tree reading it suffices for the residual (the certificate leg aside); 033 states no rate and no model". Fix: one qualifying clause in R-1, R-2, KI-4 and the report; no Lean change. (This is an imprecision, not a false claim: under the model of record the theorems are what they say.)

3. **The definition of record clamps every sentence; the program clamps `S_k`; the literal form is refuted only in probes.** `clamp Q` (ledger: Fidelity "exact") applies the clamp to all sentences, where §3.2(d) says "on `S_k`". The gap is harmless for the refutation — `⊥ ∈ S_k` for every `k` (`smallOn_falsum`), so the `S_k`-scoped clamp floors `⊥` too: probe `ClampSmallOnly.lean` (`clampSmall_not_isLogicalInductor`), and the fidelity auditor's `E1cRefuted.lean` proves the `E1c` form. Fix: label `clamp`'s fidelity "variant: every sentence (the program: `S_k`)" and add the one-line `E1c`/`S_k` corollary as a row, so the literal §3.2(d) form is refuted in the package and not only in audit probes.

4. **Kind and hypothesis nits.** `clamp_not_isLogicalInductor` is the composition of `sellBottom_ec`, `sellBottom_exploits` and `clamp_mem_Icc` (kind `C`, labelled `P`); `exists_settle_day` is a one-line corollary of `bridge_lemma` (kind `L`, labelled `C`); `sellBottom_exploits`/`floor_not_isLogicalInductor` carry `hP0 : ∀ n, 0 ≤ P n ⊥`, which `hP` and `epsK_pos` already give (harmless, but an auditor reading "any market with the floor" should not think a second condition is needed).

5. **Fidelity label "exact" on T1 while the docstring lists four deltas.** `overlay_isLogicalInductor`/`'` are "exact (run-level oracle for the program's (iii), Known issue 5; guard dropped, Known issue 6)", and `ExprMap` additionally adds `ov_range` (R-6) and lets leaves read earlier days. Each delta is disclosed and argued, but STANDARDS §4's vocabulary for this is `variant: <how>`; the parenthetical carries the content, so this is presentation. Same for `EfficientlyComputable.spliceOn` ("exact").

Presentation, already on record: the 23 `DOC` warnings in `AttemptA/` (R-10); attempt B's `bli-transfer-B-open.txt` at package level (R-8).
