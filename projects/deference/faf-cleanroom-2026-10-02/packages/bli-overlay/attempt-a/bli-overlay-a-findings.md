# `bli-overlay` (attempt A) — findings

Findings about the sources ([STANDARDS](../../../STANDARDS.md) §5): the mandate's five Known issues, confirmed or refined, and new items. Severity: **blocking** (the note's conclusion fails) / **local error** / **imprecision** / **presentation**. Pointers are to `bli-program` (`run/survey/bli-program.md`), `bli-overlay-mandate`, and the Lean.

## The mandate's Known issues

**F-1 (Known issue 1, confirmed; local error in the program's sketch).** `bli-program` §2.1 (F2 paragraph) compares the firm's *token count* (`≈ n·n(n+1)^n`) with `sizeBound n = 2^{2^n}` and concludes the inclusion "from `n = 4` on". The token count is the wrong quantity: the size of a sentence a `P`-digit stream can name is exponential in `P` (`bli-found`'s `bridgeBound C P ≤ 2^((C+6)(P+1))`), and the index-`j` clock `progClock j n = a (n+1)^k + a` has degree `k = progDeg j = (Nat.unpair j).2`, which for `j ≤ n` is bounded by `√n` and not better. The honest comparison is `2^((C+6)(progClock j n + 1))` against `2^{2^n}`, i.e. `(C+6)(n (n+1)^{√n} + n + 1) ≤ 2^n`, which holds from `N₀ = 2^10 + 4C + 32` on (`eventually_firm_clock_le`; `1096` at `C = 10`), not from `n = 4`. The target stands (`firm_mentioned_small`), and `sizeBound` needs no change. The estimate in the mandate ("`(C+6)(√n·(n+1)^{√n}+…)`") is right; the proof does not even need the coefficient's square-root bound (F-7).

**F-2 (Known issue 2, confirmed; imprecision).** The plan's F2 wording (`support … ⊆ smallSet n`, `bli-program` §4 row F2) is weaker than what §3.3 (i) uses (the price leaves included). The headline is the `MentionedBy` form `firm_mentioned_small`; the support form `firm_support_subset_smallSet` is its corollary through `support_subset_mentionedSet`, marked `Fidelity: weaker`.

**F-3 (Known issue 3, confirmed; presentation).** The plan's angle-B wording names `liaTrader_not_exploited` as the lemma that "applies unchanged"; the trader-generic lemma is `marketMaker_not_exploited` (`MarketMaker.lean:1547`). On angle A neither is used: T4 goes through `MarketMaker_accepts` → `dayValue_le_of_accepts` → T3(a) with `W = ∅` → `trading_firm_dominance`, and `liaTrader_not_exploited` is recovered only as the zero-overlay instance via `overlayQuote_zero_eq_liaQuote`. Confirmed as well that both angles define the states before any trader: attempt A's `firmStrat DP ov n := TradingFirmAt DP (overlayQuote DP ov) n` is a definition *after* `dayRec`, and the recursion's own strategy `dayStrat` is tied to it by `dayStrat_eq_firmStrat`.

**F-4 (Known issue 4, confirmed and extended; imprecision in `bli-program` §3.3 (i)).** §3.3 (i) says the market-maker argument "is indifferent to what the history says *off that support*, on that day and on earlier days". Two corrections. (a) *Earlier days*: the firm's coefficients carry price leaves at earlier days (the enumerated traders' features are arbitrary `EF`s of rank `≤ n`), so the indifference is off the strategy's *mentioned set*, not off its support — T1 is exactly the right congruence, and `mentionedBy_TradingFirmAt` shows those leaves come only from the enumerated traders' own coefficients; the budgeter reads earlier days as *data* (`rawPriorWorthRat`, `priorBudgetBreach` sit inside `EF.const` and the `if` of `BudgeterAt`), never as leaves. (b) *That day* (new): the same holds on day `n` itself — an enumerated trader may read `price ψ n` for a `ψ` it does not trade, so a day-`n` overlay must stay off the *mentioned* set, not merely off the support. The budgeter's own day-`n` leaves (`worldValueFeature` carries `price φ n` for traded `φ`, `mentionedBy_of_mem_priceQueries_worldValueFeature`) are inside the support and cause no extra restriction. Nothing breaks: D3 overlays outside `mentionedSet (firmStrat n)`, which is what the mandate specifies; the program's prose overstates.

**F-5 (Known issue 5, confirmed with a proof; presentation).** `mentionedSet (TradingFirmAt DP Q n)` does not depend on `DP` or `Q`: `mentionedSet_TradingFirmAt_eq : mentionedSet (TradingFirmAt DP Q n) = (Finset.range (n+1)).biUnion fun j => mentionedSet ((enumeratedTrader j).strat n)`. The program's F2 quantifies `∀ Q` as if the set might vary; it does not. The quantifier is still the right one for the *statement* (the overlaid table is not `liaQuote`), it is just vacuous for the *set*.

## New findings

**F-6 (mandate T2 step 3; presentation).** The mandate's route asks for square-root bounds on *both* `Nat.unpair` components (`progCoeff j ≤ √n` and `progDeg j ≤ √n`). Only the degree's bound is load-bearing: with `progCoeff j ≤ j ≤ n` (the crude `Nat.unpair_right_le`/`unpair_left_le`) the exponent is `1 + (l+1)(s+1)` instead of `≈ (l+1)(s+1) + log s`, and the eventual inequality `C + 7 + (l+1)(s+1) ≤ n` is unaffected. `unpair_snd_le_sqrt` is the one square-root lemma the proof uses (both branches of `Nat.unpair` are `≤ Nat.sqrt`, from `Nat.lt_succ_sqrt`).

**F-7 (mandate T2 step 3; presentation).** The mandate suggests "`(n+1)^{√n} ≤ 2^{n/2}` eventually, from `n + 1 ≤ 2^{√n/2}`". The proof used a different decomposition, exponent-first: `(n+1)^{s+1} ≤ 2^{(l+1)(s+1)}` and then `(l+1)(s+1) ≤ n − C − 7` from `2(l+1) ≤ s`, itself from `4(l+1)^2 ≤ 2^l` for `l ≥ 10` (`four_mul_sq_succ_le_two_pow`, a two-line `Nat.le_induction`). `bli-found`'s `eventually_poly_le_two_pow` pattern (through `Nat.log`) was imitated as the mandate says, not applied.

**F-8 (FAF API request; presentation).** `LogicalInduction.quoteFromEntries_map_eq` (`MarketMaker.lean`, the lookup lemma for `l.map (ψ ↦ (ψ, f ψ))`) is `private`; attempt A re-proves it verbatim (`Recursion.lean`, `quoteFromEntries_map_eq`) for `restrictState_quote_of_mem`. Making it public would remove the duplicate.

**F-9 (mandate T5 route; presentation).** The witness day `n := max N₀ 1` is unnecessary: `bli-found`'s `largeOn_witness n : ¬ SmallOn n (Formula.atom (4 ^ sizeBound n))` holds for every `n` (including `0`), so `n := N₀` suffices (`overlay_half_ne_lia`). Also the mandate's optional `overlayQuote_eq_lia_on_mentioned` is false for a nonzero overlay in general (the firm reads the overlaid past, so its day-`n` strategy and mentioned set differ from the LIA's); it was not stated.

**F-10 (the T2 witness's day; note for auditors, not a defect).** `firm_mentions_something` exhibits the day `i` as the enumeration index of FAF's `buyAtomDaily` from `exists_enumeratedTrader_eq`, whose proof runs through complexitylib's `exists_desc_computesInTime_clock`; the index is existential, and no concrete day was computed (computing one would mean evaluating a TM compilation — the `decide`-on-FAF cost the bli-found orchestrator note warns about). The witness is graded N+ on the strength of the construction (a real firm, a real sentence that varies with the day, every `DP` and `Q`); an auditor wanting a numeric day should not expect one from this route.

**F-11 (T3(a)'s quantifier; presentation, positive).** The waived-days lemma is stated over **every** `PCWorld`, not only worlds consistent with `DP.D n`, and its proof needs no process at all — the same unconditional shape as FAF's `marketMaker_day_value_le`. Consequently `not_exploits_of_dayValue_le_off_finite` holds for a `DP` all of whose stages are unsatisfiable, where `Exploits` is empty anyway; the N+ at `paperDP 𝗜𝚺₁` (`overlay_half_paperDP_hworld`) is what shows the theorem is not empty at its use.

**F-12 (mandate T3(c) witness; resolved).** T3(a)/(c) with `W ≠ ∅` is exercised by the waived recursion (`WaivedRecursion.lean`, T7): `waived_firm_not_exploited` applies T3(a) with an arbitrary finite `W`, and `waivedRec_empty` shows the `W = ∅` case is the unwaived recursion. What remains unexhibited is a *numeric* `W ≠ ∅` day (a concrete prescribed state on a concrete day), which nothing here needs.

**F-13 (mandate T7 wording; presentation).** The mandate says angle A's T7 is "immediate (skip the search on `W`)". Confirmed: the change is one `if n ∈ W then pre n else dayCore …` in the day step; every D3 identity re-proves by the same script, and the T4 proof is reused verbatim off `W`. The mandate's remark that on angle B "the waived days [are] handled by T3(a) after all" is consistent with this: on angle A too, T7's no-exploitation is T3(a) with the given `W` — the past-view trick is not what carries it on either angle.

**F-14 (T6, the shape of the open item; presentation, for the reconciler and `bli-coherent-mm`).** With `Computation.lean` the only unproved link between `overlay_no_ec_trader_exploits` and `IsLogicalInductor (overlayHistory DP ov) DP` is the inhabitation of `OverlayBoundedEvaluatorCompiler process ov` — `Computable₂` of the natural-coded bounded evaluator. It is a genuine open item of size L–XL (FAF's own certificate for the LIA is `LIACompiler.lean`, 4041 lines), and it depends on `ov`: for an `ov` that is not a computable function of the encoded records, the certificate is false, so any claim of L6(b) for the BLI must name the overlay's computability (the Tier-B tent values of `bli-superbelief`'s `tentExpr` are computable terms; B3's coherent world measure is a search). The mandate's expectation `partial: computability open` is met, with the open part now a single named structure rather than a prose gap.
