## 3. Non-blocking issues

**3.1 (ledger/report; presentation) The numeric constants are readings of proof terms, not Lean statements.** `firm_mentioned_small_from hC : ∀ n ≥ (C + 16)^2, …` is a theorem, but `676` needs `C = 10`, which lives inside bli-found's `tokenSize_le_of_structured : ∃ C, …` (`refine ⟨10, _⟩`, `Structured.lean:605`) and is not exposed by any lemma; likewise attempt A's `eventually_firm_clock_le (C) : ∃ N₀, ∀ n ≥ N₀, …` has `1024 + 4*C + 32` only in its proof, so the ledger row "`n ≥ 2^10 + 4C + 32`" and "`AttemptA.firm_mentioned_small` at `N₀ = … = 1096`" describe proofs, not statements. The report and ledger read as if `676`/`1096` were checked numbers. Fix I'd accept: say "by reading the proof term" in both rows, or (better) an FAF-API-style request to bli-found for `tokenSize_le_of_structured_ten` with the constant in the statement, after which `firm_mentioned_small_from` gives `∀ n ≥ 676, …` as a theorem (probe §4 shows the arithmetic reduces). Attempt A's arithmetic could state its constant.

**3.2 (ledger; presentation) The "(b)" label on the two conditional rows.** `overlay_isLogicalInductor_of_computableMarket` lists `hmarket : ComputableMarket (overlayHistory DP ov)` as "(b)", and `OverlayBoundedEvaluatorCompiler.toComputableMarket` / `overlay_isLogicalInductor_of_compiler` list `compiler` as "(b)". [STANDARDS](../../STANDARDS.md) §3 defines (b) as "a published theorem taken as stated because FAF lacks it (name the paper and theorem)"; these are unproved targets (L6(b)), not citations. The Status column (`partial: computability open`) is the honest part and is right; the provenance column should say "open target L6(b), taken as a hypothesis" rather than (b). Same in the docstrings' `Hyps:` lines.

**3.3 (findings F-1; wording) An upper bound stated as attained.** F-1 says "the size of a sentence a `P`-digit stream can name is exponential in `P`". What the package uses is bli-found's *upper* bound (`bridgeBound C P ≤ 2^((C+6)(P+1))`, through the structured escape `tokenSize_le_of_structured`); nothing here shows a `P`-digit stream actually names a sentence of exponential size, so nothing here shows the program's "below `2^{2^n}` from `n = 4` on" is *false* for the real firm — only that the program compared the wrong quantity (token count against `sizeBound`) and that the honest proof lands at `N₀ = (C+16)^2`. The severity ("local error in the program's sketch; the target stands") is fair on the wrong-quantity ground; the sentence should read "bounded by an exponential in `P` (bli-found's bridge bound), with no better bound available", unless bli-found has an attainment witness (I did not check bli-found's findings for one).

**3.4 (T5 witness; presentation, for customers) The exhibited price change is at a large sentence only.** `overlay_half_ne_lia` and `overlay_half_differs_from` change the price of `⌜a_{4^{sizeBound n}}⌝` (an atom of index `4^(2^(2^n))` at `n ≥ 676`): a real sentence on a real `paperDP 𝗜𝚺₁` day, so N+ by the mandate's own grading rule ("a real `paperDP` day and the overlay changes a price"). But the BLI's use of Route O is Tier-B values on *small-but-unmentioned* sentences (mandate Context, `bli-program` §3.3 (i)), and no witness shows the overlay firing on a small sentence — which would need a concrete day's mentioned set, banned by cost (mandate T5, last sentence). The ledger's witness column should say "at the day's large atom; no small unmentioned sentence exhibited (cost)", so a reader of the N+ does not infer more than is shown. The witness day: the record's `overlay_half_ne_lia` is `AttemptA.overlay_half_ne_lia`, whose `N₀` comes from `AttemptA.firm_mentioned_small` (`1096` by reading), not from the record's T2 (`676`); immaterial to the `∃ n φ` statement, but the reconciled docstring's "On T2's day `N₀`" silently means attempt A's.

**3.5 (D1 docstring; presentation) `MentionedBy`/`mentionedSet` are syntactic.** A trade whose coefficient is `mul (const 0) e` still "mentions" its sentence and its leaves, so `mentionedSet` is a superset of the set of cells the strategy's value actually depends on. This is the safe direction for every theorem here (the overlay fires on fewer sentences; T1 is a congruence over a superset), it is bli-found's definition, and the mandate's D1 asks for it — but the reconciled D1 docstring should say "syntactic; a superset of the semantic dependence set" so that `firm_mentions_something` (which certifies a syntactic mention through `scaleConst`ed components) is read for what it is.

**3.6 (T2 witness vs T2's day; presentation) Unrelated existentials.** `firm_mentions_something : ∃ i, ∀ n ≥ i, …` and `firm_mentioned_small : ∃ N₀, ∀ n ≥ N₀, …` have independent thresholds; the witness shows F2 is about a nonempty set only for `n ≥ max i N₀`. Nothing is wrong (from that day on it is nonempty for every `DP`, `Q`, with a day-varying sentence, which is genuinely N+); the ledger's witness column could say so in four words.

**3.7 (report; presentation) The `LIAComputation.lean` day-step reading.** The mandate asks both attempts to record it in their reports; the reconciled report summarises it in one paragraph and points to the attempts' reports. I confirmed both attempt reports discuss `LIAComputation` but did not audit those sections against the FAF file; a round-2 auditor with the adversarial lens may want to.
