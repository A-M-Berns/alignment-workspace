# `bli-overlay` — report (reconciled)

The dual package `bli-overlay` (area `bli`, namespace `Cleanroom.Bli.BliOverlay`, directory `Cleanroom/Bli/BliOverlay/`, root `Cleanroom/Bli/BliOverlay.lean`): the overlay construction (Route O) — the firm-support lemma, the waived-days lemma, the overlaid market-maker recursion. Mandate: `bli-overlay-mandate`. Two independent attempts — A, the restricted-past recursion ([bli-overlay-a-report](attempt-a/bli-overlay-a-report.md)); B, the past-view trader ([bli-overlay-b-report](attempt-b/bli-overlay-b-report.md)) — each reached every core target sorry-free. Reconciler: one agent (Claude Fable 5.1, [scrubbed]), 2026-09-30, per `run/prompts/reconcile.md`.

## State of the package

- **Every target of the mandate is proved, by both attempts, and the two attempts' constructions are proved to be the same object.** The reconciled modules state each target once over the definitions of record and prove it by the better attempt's route; `CrossCheck.lean` proves that attempt A's and attempt B's recursions return the same core states and the same overlaid table on every day (`coreState_quote_eq_attemptB`), so there is no disagreement anywhere in the package.
- **The three load-bearing headlines are at grade (a) with N+ witnesses**: T4 `overlay_no_ec_trader_exploits` (L6(a): no efficiently computable trader exploits the overlaid market, for every process and every overlay; witnessed over `paperDP 𝗜𝚺₁` with `Overlay.half`, which provably changes a price), T3(a) `not_exploits_of_dayValue_le_off_finite` (the waived-days lemma, with its firm corollary T3(c) and the customer's entry point `dayValue_le_of_accepted_state`), and T2 `firm_mentioned_small` (the firm-support lemma, uniform in `DP` and `Q`, at `N₀ = (C+16)^2 = 676` for the structured constant `C = 10`, with an independent second proof at `N₀ = 1096`).
- **The recursion of record is attempt A's** (FAF's `MarketMaker` on the firm built from the overlaid table, against the restricted overlaid past); attempt B's characterisation of the states as FAF's `marketMakerStates` of a trader transports to it (`coreState_eq_marketMakerStates`), so the package holds both readings. The sanity identity `overlayQuote_zero_eq_liaQuote` holds: with the zero overlay the recursion is FAF's LIA.
- **T7 (extension) landed** (`waived_no_ec_trader_exploits`; `W = ∅` is the record's recursion). **T6 (stretch) is `partial: computability open`** as the mandate expects: both attempts built the fuel-bounded evaluator with soundness and the compiler boundary with `toComputableMarket`; neither instantiated the boundary, and no Lean statement carries a `sorry` (`bli-overlay-open.txt` is empty).
- **Findings**: [bli-overlay-findings](bli-overlay-findings.md) — the mandate's five Known issues confirmed by both attempts (1 and 5 with proofs), ten further items from the attempts consolidated, and four reconciliation items (R-1: the cross-check, proved; R-2: why angle A is of record; R-3: the entry point's two shapes; R-4: what was not cross-checked).
- **Contamination**: none. I did not read, list or grep `research/faf-lab/`, any transcript, or git history. Sources read: the mandate; both attempts' reports, ledgers, findings and open lists; the attempts' Lean (declaration lists, and the windows named in §Two attempts); `run/prompts/00-common.md`, `STANDARDS.md`, `run/prompts/reconcile.md`; `research/lean-deference/AUDIT.md` §0.2 and §3; FAF's `MarketMaker.lean` (`786–815`, `1365–1385`) and `TradingFirm.lean` (`670–680`); bli-found's `Size.lean` declaration list and `Structured.lean:601–604`; `scripts/README.md`. ### Disagreements

**None.** Every target is proved by both attempts; the two definitions of D3 differ only in what is fed to `MarketMaker` (the bare firm against the restricted overlaid past, versus the past-substituted firm against the core past), and `coreState_quote_eq_attemptB` proves the two produce the same states and tables for every process, overlay and day. The mandate's prediction ("they should: `MarketMaker` depends on its inputs only through the mentioned cells") is confirmed as a theorem. The only *numerical* difference between the attempts is T2's constant (`676` against `1096`), which is a difference of estimate, not of claim.

- **D2, D3: attempt A's recursion** (`AttemptA.dayRec`, read off as `coreState`, `overlayQuote`, `overlayHistory`, `corePast`, `firmStrat`, `overlayRestrictedPast`). ### The cross-check (`CrossCheck.lean`)

`coreState_quote_eq_attemptB (DP) (ov) (n) : coreState DP ov n = AttemptB.coreState DP ov.toB n ∧ ∀ φ, overlayQuote DP ov n φ = AttemptB.overlayQuote DP ov.toB n φ`, by strong induction on the day. At day `n`: the firms coincide (`TradingFirmAt_eq_of_eq_prefix`; both read the overlaid table below `n`, equal by the induction hypothesis), hence the mentioned sets; the core pasts coincide (induction hypothesis on the states); and the market makers coincide by `AttemptB.MarketMaker_congr`, because for every candidate `B` acceptance of the bare firm against the restricted overlaid past is acceptance of the past-substituted firm against the core past — same support (`Strategy.support_substPast`), and the same exact value on the two candidate histories (`Strategy.marketValueRat_substPast` turns the substituted firm's value into the bare firm's value on the rational past view, and T1 closes: at a mentioned past cell the past view reads `quoteBelow`, i.e. attempt B's overlaid value, equal by the induction hypothesis to attempt A's, which is what the restricted past lists — `rationalHistory_overlayRestrictedPast`; on day `n` both read `B.quote`). The quotes then agree cell by cell (`simp only` with the three equalities). Corollaries: `coreState_eq_attemptB`, `overlayQuote_eq_attemptB`, `overlayHistory_eq_attemptB`, `firmStrat_eq_attemptB`; the transported `coreState_eq_marketMakerStates` (the record's states are `marketMakerStates (AttemptB.pvTrader DP ov.toB)`); `overlay_firm_not_exploited_via_marketMaker`; in `Witness.lean` the transported `overlay_half_differs_from` and `overlay_plausibleAssessments_nonempty`. The proof is 60 lines and elaborated on the first attempt.

## Interface notes for dependents

1. **`bli-coherent-mm`** (M3, the coherent market maker): import `Cleanroom.Bli.BliOverlay` and use D1–D3 by their record names; the acceptance lemma for a *different* maker is `dayValue_le_of_accepted_state` (arbitrary table with the acceptance-style bound; or `_split` for a past + accepted state). The waived shape for initial segments is `WaivedRecursion.lean`.
2. **`bli-exact-base`** K7 (the finite-segment splice) uses T3(a)'s shape with `W ≠ ∅`; T7 is its worked instance.
3. **`bli-assemble`'s `fullMixture`**: an overlay is any `Overlay` (finite data with a `[0,1]` proof); `overlay_no_ec_trader_exploits` holds for all of them. L6(b) for a concrete overlay needs the overlay's computability named (findings F-15).
4. **Attempt B's devices** (`AttemptB.Strategy.substPast`, `marketMakerAccepts_substPast_iff`, `MarketMaker_congr`) are imported by the root and usable; `MarketMaker_congr` is the cleanest tool for "two market-maker invocations agree".
