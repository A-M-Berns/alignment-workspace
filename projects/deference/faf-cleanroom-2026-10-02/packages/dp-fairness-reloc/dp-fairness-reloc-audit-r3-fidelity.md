**What the Lean says.** Both statements are true, and true for the trivial reason [STANDARDS](../../STANDARDS.md) §3 names for N−: `degen_value : ∀ C, value C degen = 0` — one value regardless of `C`; `contLaw_spur : ∀ C, contLaw C spur = single (( ), 1) 1` — one law regardless of `C`. `degen` is moreover **law-fair** (every leaf `(( ), 0)`, so both fiber members have law `δ_{(( ),0)}` under every `C`), i.e. it is itself law-spurious nesting: it witnesses the `≈_law` clause, and says nothing about `≈_val` beyond it. The row concedes the degeneracy and claims it is forced ("the best available … rejected whenever the nested point changes the value").

**What is actually true** (probe `ValFairNested.lean`, all machine-checked):

- `vnTop := decision d (a ↦ vnA, b ↦ vnBot)`, `vnA := decision d (a ↦ ½-coin over payoffs 0 and 2, b ↦ 0)`, `vnBot := decision d (a ↦ 1, b ↦ 0)`; one point, `Unit` worlds, payoffs `0, 1, 2`. - `valFair_nested_nondegenerate : Nested vnTop () ∧ FairWrt (fun _ => ValEq) vnTop ∧ ¬ LawFair vnTop ∧ ∀ q h0 h1, value (procQ q h0 h1) vnTop = q`. The nesting is positive (no chance node on the `b, a` path); `Fair_{≈val}` is in the source's own grade (`ValEq`, equal `V_T(C)` for every `C`); **not** law-fair because under `d ↦ a` the members `vnA` and `vnBot` have laws `½δ₀ + ½δ₂` and `δ₁` (`vnTop_not_lawFair`, evaluated at `(( ), 1)`); and the value `q` **varies with the procedure**, so the nested point changes the value and `≈_val` does not reject it.

So: the `≈_val` clause has a witness that the `≈_law` clause does not already cover, and with a value that moves; "the best available" and "rejected whenever the nested point changes the value" are false, and F13's "needs the nested point to leave the value unchanged under every procedure" is false. (The one thing `vnTop` shares with `degen` is that the *top node's own* choice is value-inert — `vnA` and `vnBot` have the same value function — which is what `≈_val`-fairness of a nested pair forces by definition; that is not what the row or F13 says.)

**Why blocking.** `audit.md`: "an N+ claim that is really N−" and "a false claim in the findings file". Both are present, on the row that round 2 was blocked to create. The fix is small and the probe supplies it.
