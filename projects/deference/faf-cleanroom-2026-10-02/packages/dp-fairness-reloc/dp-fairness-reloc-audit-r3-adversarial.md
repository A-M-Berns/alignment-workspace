## 2. Blocking issues

### B1. `degen_fairValEq` and `spur_lawFair` (the EQ-4 `≈_val` and `≈_law` clause witnesses) are graded N+; both are payoff-constant trees on which the relation holds for a reason independent of nesting, so N−; and the ledger's "the best available for the every-`C` grade" is false

**Declarations / rows.** `degen_fairValEq : FairWrt (fun _ => ValEq) degen ∧ Nested degen ()` (`AuditWitnesses.lean` 159, docstring `Kind: N+ (the clause's content: a nested tree passes the every-C value grade; the witness is payoff-degenerate — …)`); ledger row 71: "N+ (payoff-degenerate: every value `0`; **the best available for the every-`C` grade** — a non-degenerate nested tree is rejected by it whenever the nested point changes the value, as E5 shows)". `spur_lawFair : LawFair spur ∧ Nested spur ()` (`AuditWitnesses.lean` 221, `Kind: N+`, `Fidelity: exact`); ledger row 73: "N+ | exact". Both are bundled as N+ in `eq4_val_law_clauses` (row 74) and cited in report §T9, findings F9 ("the `≈_val` clause on Claim F's payoff-degenerate tree (`degen_fairValEq`)") and F13 ("every-`C` value fairness admits only payoff-degenerate nesting on the witnesses at hand").

**What is wrong.** `degen` has every payoff `0`, so `value C degen = value C' degen` for *all* `C, C'` (probe `probe_degen_value_constant`; the library's own `degen_value`/`degenBot_value`) — `ValEq` between its top and bottom holds because every value on the tree is the constant `0`, and would hold between any two zero-payoff trees whatever their shape. `spur` has every leaf `(( ), 1)`, so `contLaw C spur = δ_{(( ),1)}` for every `C` (`probe_spur_law_constant`; the library's `contLaw_spur`) — `LawEq` holds because the law is constant, not because of anything about the nested query. This is [STANDARDS](../../STANDARDS.md) §3's N− pattern ("not constant sequences"): the witness inhabits the hypothesis package but does not exercise the content of the clause, which is that *a nested query can be invisible to the law/value grade while the tree has real law and value content*. Round 1 blocked on the same pattern (`gr3` on `Unit` worlds, `twoSeq` without chance); the round-2 repair adopted these two from the fidelity auditor's "for completeness" probe with N+ labels and no adversarial grading.

**Evidence that "the best available" is false** (probe `NonDegenSpurious.lean`, all machine-checked): `nb := decision d (a ↦ leaf () 1, b ↦ leaf () 0)` and `spurTop := decision d (fun _ => nb)` — a `d`-node both of whose children are one and the same non-degenerate `d`-node. `probe_nondegen_nested_val_law` bundles: `Nested spurTop ()` (positive path, count `2`, two actions), `¬ AlmostFair spurTop`, `¬ StronglyFair spurTop` (node count `3 ≠ 5`), `value (procQ 1) spurTop ≠ value (procQ 0) spurTop` (the value is `q` under `procQ q`, `probe_spurTop_value`, so values and laws vary with the procedure — non-constant), and `LawFair spurTop ∧ FairWrt (fun _ => ValEq) spurTop ∧ ValueFair spurTop`. The mechanism is exactly the one the source's phrase "law-spurious nesting" names: `contLaw C spurTop = ∑_a C(d)(a) • contLaw C nb = contLaw C nb` (`probe_contLaw_spurTop`, the weights sum to one), so the nested query is invisible to the `(λ, r)`-law because its children are law-equal — not because the payoffs are flat. So the ledger's parenthetical "a non-degenerate nested tree is rejected by `≈_val` whenever the nested point changes the value" is right, and its "the best available" is not: a nested tree with non-constant values passes both the `≈_val` and the `≈_law` grade.

**Why blocking.** `audit.md` §2: "an N+ claim that is really N−". Two rows, and the N+ justification offered for one of them is refuted.

**Fix I'd accept.** Adopt `nb`/`spurTop` (with `probe_contLaw_spurTop`, `probe_spurTop_subtree`, `probe_spurTop_nested`, `probe_spurTop_lawFair`, `probe_spurTop_fairValEq`, `probe_spurTop_valueFair`, `probe_spurTop_value`, `probe_spurTop_not_constant`, `probe_spurTop_not_stronglyFair`) into `AuditWitnesses.lean` as the N+ for both the `≈_val` and the `≈_law` clause (one tree witnesses both, and the act-value grade too); regrade `degen_fairValEq` and `spur_lawFair` N− in their docstrings and rows ("payoff-constant: the relation holds for every `C` for a reason independent of nesting"), and strike "the best available for the every-`C` grade" from row 71; reword F13's last paragraph and F9's `≈_val` sentence so that "admits only payoff-degenerate nesting" becomes "admits nesting exactly when the nested query is law-inert — `spurTop` (non-constant) as well as `degen`/`spur` (constant)". Minimal alternative: regrade the two rows N− and carry the non-degenerate witness as `flagged: probe supplied`.
