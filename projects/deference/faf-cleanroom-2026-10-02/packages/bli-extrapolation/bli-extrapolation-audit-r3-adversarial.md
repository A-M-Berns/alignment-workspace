## 2. Blocking issues

### B1. `decay_scheme_is_half_rule` (4c(ii), `Decay.lean:204`): Fidelity "exact" for PDF 06 eq. (1), but only the `m = 0` instance of the source's scheme is proved; the base-given `r` of the source is not covered

- **The source.** PDF 06 p. 2, verbatim from `pdftotext`: "If we know $P_n(\forall m\varphi(m))$, but not all the $P_n(\varphi(1)\wedge\dots\wedge\varphi(m))$, we can settle on a 'max-entropy-ish' distribution for them that respects all constraints we have. For example, if we only have information up to $\varphi(m)$, we can set $r := P_n(\varphi(1)\wedge\dots\wedge\varphi(m)) - P_n(\forall m\varphi(m)) \ge 0$, and define $P_n(\varphi(1)\wedge\dots\wedge\varphi(k)) := P_n(\forall m\varphi(m)) + r/2^{k-m}$ (1) for $k \ge m$." The content of eq. (1) is that the base fixes `P(ϕ(1..m))` — hence `r` — arbitrarily, and the scheme extends it by halving. The mandate's wording points the same way: "under `HalvingCondition` *from level `m` on*".
- **The Lean.** `decay_scheme_is_half_rule` (statement, `Decay.lean:204–215`): hypotheses the unpacked `HalvingCondition` with `hkB : B ≤ k 0`, `hinst : ∀ n, S.inst u (i n) = atom (e (k n))`, `hhalf`, and `hmn : m ≤ n`; conclusion `extrapolateVal S e q (instPrefix (fun j => S.inst u (i j)) n) = P(U) + (extrapolateVal S e q (instPrefix (fun j => S.inst u (i j)) m) − P(U)) / 2 ^ (n − m)`. Every instance in the `m`-prefix is `atom (e (k j))` with `k j ≥ k 0 ≥ B`: beyond the base, at a halving level. So `decay_scheme_pow` at `m` already gives `P(⋀_{j<m}) − P(U) = (½)^m · P(¬U)` — the "`r`" is produced by the rule, not given by the base — and the proof body (`:216–221`) is literally `rw [decay_scheme_pow … n, decay_scheme_pow … m]`, a `Nat.exists_eq_add_of_le`, `pow_add`, `ring`. The `m ≥ 1` cases add nothing to `decay_scheme_pow`; the one case that is the source's display is `m = 0` (the base knows `P(U)` and no instance, `r = P(¬U)`).
- **What claims more than is proved.** Ledger row 4c(ii), Fidelity: "exact (prefix `j < n`, indices from `0`; the source's display mixes `φ(0)`/`φ(1)`, F-4)". Docstring: "Fidelity: exact (prefix `j < n` over the instances at the halving levels; …)". Report §4c(ii): "Fidelity exact for the prefix `j < n` over the instances at the halving levels". F-4: "So eq. (1) is not a further proposal but the ½-rule read off along the halving levels" and "`decay_scheme_is_half_rule` is the display itself". The parenthetical "at the halving levels" discloses the restriction to a reader who already knows what it costs; "exact" says the opposite. The name `decay_scheme_is_half_rule` promises eq. (1).
- **Evidence that the gap is real and the fix cheap** (probe `AdvDecayBasePrefix.lean`, elaborated): `decay_scheme_general` — for any sentence `E₀` with `level e E₀ ≤ k 0`, `P(E₀ ∧ ⋀_{j<n} a_j) = P(U ∧ E₀) + (½)^n · P(¬U ∧ E₀)`; `eq1_base_prefix` — for `E₀ = instPrefix (fun j => S.inst u j) m` at any levels `≤ k 0` (in particular inside the base), `P(E₀ ∧ ⋀_{j<n} a_j) = P(U) + (P(E₀) − P(U)) / 2^n`, which is eq.
