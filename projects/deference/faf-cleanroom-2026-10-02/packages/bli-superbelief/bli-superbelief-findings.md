# `bli-superbelief` — findings about the sources

Findings about the research ([STANDARDS](../../STANDARDS.md) §5), each with a severity (blocking / local error / imprecision / presentation) and a pointer. Every "the author meant" sentence is ATTRIBUTION-UNVETTED. Refutations that are proved in Lean name the declaration (namespace `Cleanroom.Bli.BliSuperbelief`). The mandate's eleven expected items are F-1…F-11; F-12 onward are new (F-12 is the important one: a false constant in the program of record).

## F-1 — bli-slides-017: the printed grid omits 0, so exact constraint 1 fails below `1/d` (local error; refuted)

- Pointer: [AISC 2025 - Roman - BLI beliefs-about-future-beliefs.pdf](../../sources/references/bli/slides/AISC%202025%20-%20Roman%20-%20BLI%20beliefs-about-future-beliefs.pdf) pp. 2–3, `D = {1/d, …, 1}`; bli-slides-017's flag; `bli-program` §3.4 Boundary.
- Finding: with `0 ∉ D`, every grid point prices every small sentence at `≥ 1/d`, so constraint 4 forces `𝐏_n(φ) ≥ 1/d` for every small `φ` (`posGrid_mean_ge`), and exact constraint 1 (`𝐏_n(φ) = 𝐐_n(φ)`) is unsatisfiable on any day whose small set contains a sentence priced below `1/d` — a propositional contradiction priced `0`, for instance (`posGrid_no_balance_below`; N− `posGrid_witness` at `d = 2`, `S = {⊥}`, `t ⊥ = 0`). The refuted object `posGrid` is defined only to state this and is not of record.
- Surviving neighbour: `bli-finite`'s `gridVals` with `0` and `1` (`zero_mem_gridVals`, `one_mem_gridVals`), over which E1 and E2 are stated.
- Attribution: p. 17 lists "[0;1] boundaries" as a missing detail; that the author *meant* `0 ∉ D` rather than an oversight is ATTRIBUTION-UNVETTED.

## F-2 — bli-slides-018/021: full support over all of `D^S` is inconsistent with exact agreement at a 0/1 price (local error in the desiderata; refuted)

- Pointer: p. 5 (desideratum (6): `𝐏_n(𝐐_{n+1} = 𝒬) ≠ 0`, boxed without an explicit quantifier; read as "for all `𝒬 ∈ D^S`" in bli-slides-018 — the slide's point is that the delta superbelief makes every other conditional an update from `0`); bli-slides-021's two-line derivation.
- Finding: on the grid with 0 and 1 (`0 < d`), a fully supported probability cannot be balanced at a table with a `0/1` coordinate — the grid table disagreeing there carries positive mass, yet the pinning lemma forces mass `0` (`fullSupport_grid_contra_zeroOne`, `not_fullSupport_of_zeroOne`; witness `boundary_witness` at `t₀' = (p ↦ 0)`, `Q₁ = (1/2, 0)`).
- Surviving weakening: support = the product face — non-degeneracy on the face is satisfiable at every unit-cube table by the tent kernel (`nonDegenerate_face_satisfiable`), and is strictly weaker than full support exactly when `t` has a `0/1` coordinate (`faceProd_eq_grid_iff`; `nonDegenerate_yes_fullSupport_no` puts the impossibility and the weakening side by side). This is the artifact check: the impossibility is about the source's formulation, not the encoding.
- Severity: local error in the desiderata, not blocking (the weakening is natural).

## F-3 — bli-slides-020: the linear solve `f = C⁻¹ 𝐏_n` guarantees neither normalization nor positivity (imprecision)

- Pointer: pp. 11–14.
- Finding: the construction has `k = |S|` equations and `k` unknowns with normalization as a `(k+1)`-th condition, and nothing forces `F ≥ 0`. The correct existence statement is E1(ii)/(iii): a balance solution charging `Q` exists iff `t` can be backed away from `π Q` inside the hull of the restricted carrier (`faceGen_eq_hullFace`), and a fully supported one exists iff every carrier point can be (`faceGen_eq_iff_backaway`; on the product grid, iff `t` has no `0/1` coordinate, `faceProd_eq_grid_iff`). The slide's construction succeeds (as a probability) iff `t` is in the hull's relative interior — this survey's reading of what the slide needs; that this was the author's intent is ATTRIBUTION-UNVETTED.
- Severity: imprecision (the source lists "normalisation" as a missing detail, p. 17).

## F-4 — bli-slides-022: `∫ρ ln ρ → max` is entropy minimization (presentation)

- Pointer: p. 15 (read visually 2026-09-30: the slide prints `∫₀¹ ρ(x) ln ρ(x) dx → max`, the two constraints, and `ρ(x) ∼ e^{γx}`).
- Finding: `∫ρ ln ρ` is negative entropy; its maximizer under the mean constraint is a point mass, not `e^{γx}`. The conclusion `e^{γx}` is the entropy *maximizer* (minimizer of `∫ρ ln ρ`), so the sign is a typo. Severity: presentation.

## F-5 — bli-slides-023: the printed convolution matrix is off by the factor `1/2` in the off-diagonal (local error; derived, not asserted numerically)

- Pointer: p. 16 (read visually: `F_i^j = α e^{γ 𝒬_j(φ_i)}` and `C_ij ∼ [[1 … e−1], …, [e−1 … 1]]`).
- Derivation (E3(c), prose; not formalized): the basis superbelief `F_i` tilts axis `i` by `e^{γ x_i}` and is uniform on the other axes; `C_ij = C`F_i` = ∑_Q F_i(Q) Q(φ_j)`. In the continuum reading with `γ = 1` (the reading under which the diagonal is "1"): `C_ii = α ∫₀¹ x eˣ dx = α [x eˣ − eˣ]₀¹ = α · 1` and, for `j ≠ i`, `C_ij = α ∫₀¹ eˣ dx · ∫₀¹ y dy = α (e − 1) · 1/2`. So the off-diagonal-to-diagonal ratio is `(e − 1)/2`, not `e − 1`; the printed matrix would be right only if the uniform axes had mean `1` instead of `1/2`. On the finite grid the ratio is `(mean of D) · (∑_{v∈D} e^{γv}) / (∑_{v∈D} v e^{γv})`, which tends to `(e−1)/2` as `d → ∞` (with `γ = 1`, `D` with or without 0); with `D = {1/d,…,1}` the mean of `D` is `(d+1)/(2d)`. Either way `C` is invertible for the sizes in play since diagonal ≠ off-diagonal. No decimal is asserted (`plan` §0.4 rule 4).
- Severity: local error (a printed number), not load-bearing for anything formalized here.

## F-6 — bli-slides-049: computability is a hidden side condition; E1's rational solution is the fix (local error in "however we like")

- Pointer: this survey's item 049 (from FAF's `ComputableMarket`); bli-slides-005/030's "modify large sentences however we like".
- Finding: FAF's market is a computable table of rationals, so the max-entropy solution (irrational in general, E3(d) not attempted) cannot be the market. E1 gives a **rational** full-support solution on every finite carrier (`exists_fullSupport_faceGen`: an average of finitely many rational witnesses), which is the existence half of 049's LP statement; on the product grid the tent kernel is moreover an explicit `EF` term (E2). The computability half (a certificate that the solution is computable *from* `G` and `t`) is the mandate's extension and was not attempted (see the report: the `Fin`-reindexing of `bli-finite` T10 is the obstruction; `exists_fullSupport_faceGen` chooses witnesses classically, so it is not itself an algorithm).
- Severity: local error in the sources' phrasing; the fix is a side condition.

## F-9 — bli-soto-a-015 / bli-soto-a-2-007: "no added information" is ill-posed without a base measure (imprecision; both authors already say so)

- Pointer: Notion lines 254–258; Soto PDF 06 pp. 3–4 (read 2026-09-30: the `½`-chaining "(1)" and the remark that max-ent in one family forces certainty elsewhere).
- Finding (E8, prose; no Lean): a maximum-entropy / KL-projection onto the balance constraint is relative to a base law on the carrier. On the product grid with the uniform base, the projection factorizes into one-coordinate tilts *because the carrier is a product* (E3(b)'s product form uses that structure); on a non-product carrier such as the coherent grid over `extT` — whose face is not a product (`bli-finite`'s `faceGen_coherentGrid_not_prod`; here `face_witness` charges `(1,0,0)` and `(0,1,0)` while `extQ₀` is null) — no product form is available and the projection depends on which base is chosen. So "the large beliefs add no information" is well posed only once the base (carrier + reference measure) is fixed. Severity: imprecision; not formalized (E3/E8 stretch not attempted).

## F-12 — `bli-program` §2.4/§3.4 and the mandate: the tent kernel's `ℓ¹`-modulus constant `2|S|` is **false**; the correct constant is `4|S|` (local error in the program of record; refuted in Lean)

- Pointer: `bli-program` §2.4 ("piecewise affine with Lipschitz constant 2 in each weight"), §3.4 ("`‖κ(t)−κ(t')‖₁ ≤ 2|S|‖t−t'‖∞` by telescoping the product"), §3.5(iii) ("up to the kernel's modulus `2|S|/(2d(n+1))`"); mandate E2(a) ("each one-coordinate law is 2-Lipschitz in `ℓ¹` because each tent weight is").
- Finding: each *weight* is 2-Lipschitz, but the one-coordinate *law* is not 2-Lipschitz in `ℓ¹`. At `d = 2`, `tent1 2 0 = δ₀` and `tent1 2 (1/2) = U₂ = (1/3, 1/3, 1/3)`, whose `ℓ¹` distance is `2/3 + 1/3 + 1/3 = 4/3 > 2·(1/2) = 1`. On the worked witness (`|S 0| = 1`) the product law inherits it: `tentLaw_l1_two_witness` proves `∑_Q |tentLaw t₀' Q − tentLaw t₀ Q| = 4/3` with `‖t₀' − t₀‖∞ = 1/2`, so the program's bound `2·|S|·‖Δt‖ = 1` fails. The true statement: the three weights are *jointly* 4-Lipschitz (`tent_weights_lipschitz`, with equality on either side of `1/2`; the per-weight `2` gives only `6`), each coordinate law is 4-Lipschitz in `ℓ¹` (`tent1_l1_le`), and the product telescopes to `4·|S m|·‖t − t'‖∞` (`tentLaw_l1_le`, no unit-cube hypothesis). The exact one-coordinate constant is `4d/(d+1) ∈ [2, 4)`, so `2` is right only at `d = 1`.
- Consequence downstream: `bli-trajectory`'s `C:C3` modulus `2|S|/(2d(n+1))` becomes `4|S|/(2d(n+1)) = 2|S|/d(n+1)`; any statement quoting `2|S|` should be corrected. Severity: local error (a wrong constant, not a wrong theorem shape).

## F-16 — E2(d): FAF's efficiency class is **bit**-metered, so the constants' bit-size is the half of the program's size claim that matters; it was unproved in round 1 and is proved in `Bits.lean` (repair round 1)

- Pointer: `bli-program` §3.4 ("constants of `O((m−k) log d)` bits", "size `O(|S_m|·poly(m, log d))`"); mandate E2(d); FAF `Framework/Criterion.lean` (`EfficientlyComputable` at `:2083`: an `FP` function on `List Bool` read through `strategyOfOutput = strategyOfTokens ∘ unRpn ∘ undigitize ∘ bitsToDigits`, `:2070`; the docstring at `:1550–1560` and `:1605–1613`: `EfficientlyComputableDigit` "meters token *bits* rather than token values", the token layer "excludes per-day rational literals (`2^{-n}`)"); `bli-transfer`'s mandate T1.3 (`SpliceCertificate`: an `FP` map with an output-length bound polynomial in the input).
- Finding (corrected in repair round 1; the round-1 text said the measure "depends on whether" `bli-transfer`'s metric is `serialize.length` or a bit-length — false as a claim about FAF, audit r1 fidelity §2.1). `EF.serialize.length` is one list length FAF defines, but the class the criterion quantifies over is bit-metered: the strategy is emitted as a bit string, each token re-emitted as a self-delimiting base-4 digit block (`tokenBlock`, `digitize`), so a constant with a `B`-bit code costs `Θ(B)` output bits. `tentExpr_cost_le`/`tentExpr_size_le` bound the node and token counts by `88·|S(m+h+1)| + 1` and three times that — uniformly in `h` and `d` — because each rational constant is a single `const` node / a single token; they are *stronger* than the program's bound in that count and *silent* on the constants' bits, which is the half that could actually fail (exponentially growing denominators would make the term exponentially long in bits) and the half FAF meters. Their fidelity label is therefore `variant`, not `stronger`.
- What is now proved (`Bits.lean`): every chain constant `chainFrom 𝓜 m h μ v` (`μ ∈ {δ₀, U, δ₁}`) and every new-coordinate constant `coordMarg 𝓜 m h t φ v` (`φ ∉ S m`) is a probability that is an integer multiple of `1/chainDen 𝓜 m h`, with `chainDen 𝓜 m 0 = d(m+1)+1` and `chainDen 𝓜 m (h+1) = chainDen 𝓜 m h · d(m+h+1) · (d(m+h+2)+1)` (`chainFrom_den`, `coordMarg_den`, `chainFrom_isLaw`, `coordMarg_isLaw`); hence every `const q` of `tentExpr 𝓜 m h Q` has `q.den ≤ chainDen` and `|q.num| ≤ chainDen` (`tentExpr_constsBounded`), and under a mesh bound `d(m+k) ≤ D` (`k ≤ h+1`) `chainDen ≤ (D+1)^(2h+1)` (`chainDen_le_pow`) — the program's `O(h · log d)` bits. Mathlib's code of such a `q` is `Nat.pair (encode num) den < (2·chainDen + 2)²` (`encode_rat_lt`), and in FAF's digit meter `(digitize (tentExpr 𝓜 m h Q).serialize).length ≤ (K+1) · 3 · (88·|S(m+h+1)| + 1)` whenever `4^K` exceeds the day `m`, the day-`m` sentence codes and `(2·chainDen + 2)²` (`tentExpr_digitize_length_le`; explicit `K = log₄(max …) + 1` in `_log`; the mandate's polynomial form `K ≥ (4h+2)(log₄(D+1)+1) + 2` in `_poly`, via `chainDen_sq_lt_pow`). The sentence codes and the day are the other tokens; their size is `bli-found`'s (the small set's) and enters as a hypothesis on `K`.
- **Which stream the class reads** (corrected in repair round 2; the round-1 text called `digitize (… .serialize)` "what `EfficientlyComputable`'s `List Bool` output must carry" — false as a claim about FAF, audit r2 adversarial §2.1). FAF's decoder is `strategyOfOutput n w = strategyOfTokens n (unRpn (undigitize (bitsToDigits w)))` (`Criterion.lean:2070`): the recovered tokens pass through `unRpn` *before* deserialization, and `unRpn` reads the token after every price tag `0` and every trade tag `6` as a Polish-notation sentence block — the canonical symbol run `rpn φ` or the escape `[1, ⌜φ⌝]` — and contracts it to `⌜φ⌝`. A bare pair code in a sentence slot is misparsed (the audit's probe: `unRpn [0, ⌜pA ⋏ qA⌝, 3] ≠ [0, ⌜pA ⋏ qA⌝, 3]`; at `smallIndex`, where `⊥ ∈ smallSet n`, the `⊥` leaf `[0, 1, m]` would be read as an escape whose payload is the day). So the machine must emit an `unRpn`-**preimage** of the strategy stream; FAF's forward splice is `escExpand` (`Emission/RpnSentence.lean`: each sentence slot `c` becomes `[1, c]`, everything else copied; `strategyOfTokens_unRpn_escExpand` says the contraction of the expansion validates to the same strategy). Proved in `Escape.lean`: for every closed same-day term the expansion contracts back exactly under `unRpn` (`escExpand_serialize_spec`, `unRpn_escExpand_tentExpr`) and costs exactly two digits per price leaf (the escape token `1` is the block `[1, 4]`); `tentExpr` has `4·|S m|` price leaves (`priceLeaves_tentExpr` — four per sentence, not the audit's three: `wUE` reads the price twice through `absE`), so the stream FAF reads is bounded by `(K+1)·3·(88·|S(m+h+1)|+1) + 8·|S m|` (`tentExpr_escExpand_digitize_length_le`, `_poly`), and a one-trade day's whole stream `escExpand (serializeTrades [(tentExpr …, ψ)])` by that plus `2(K+1) + 2` (`escExpand_serializeTrades_single_digitize_length_le`). The escape is available at every slot because no sentence has code `0` (`encode_sentence_ne_zero`; FAF poisons code `0`).
- **Spelling** (audit r2 fidelity §3.1). The escape spelling meters a leaf by its Gödel code — the hypothesis `hA : ∀ φ ∈ S m, ⌜φ⌝ < 4^K` — and `bli-transfer`'s mandate T1.3 asks the *raw body's* leaves to be spelled as canonical runs `rpn φ` ("never as Gödel codes — a small sentence's `Encodable.encode` can be doubly exponential in its `tokenSize`"). Under that spelling a leaf costs `|rpn φ|` digit blocks (each symbol a small token), which can be exponentially less than `log₄ ⌜φ⌝` for deep sentences; FAF has no canonical-run splice function over which to state it, and this package does not state it. Constants and tags are metered identically under both spellings, so the constants' half of E2(d) — the object of this finding — is spelling-independent.
- For `bli-transfer`/`bli-assemble`: hypothesis (iii) "poly-size in `|ψ| + k`" is to be read in the bit meter, **on the escape-expanded stream**: the machine emits `escExpand (serializeTrades …)` (or a canonical-run preimage), never `serialize` itself; the statement to consume is `tentExpr_escExpand_digitize_length_le_poly` (the body's bit-length is `|S| · O(h · log d + log(max sentence code) + log m)` plus `8·|S m|`). The round-1 phrase "polynomial in the atom's own size" is `bli-assemble`'s composition, not stated here.
