## 3. Non-blocking issues

1. **`readability_ofApprox`'s Fidelity line does not say that the Lean is Lemma 2.1 *at the ledger LUV family*, which is weaker than the source's statement.** Lemma 2.1 (`route-recurring-ccee` line 72) is for *any* e.c. sequence `Z̄` of `[0,1]`-LUVs determined via `Γ_H` with values `z_n`; the Lean fixes `Z n := ledgerLuv j n`, with the determinacy from T1.2 and the e.c. certificate from T1.3. The docstring's plain statement and the row's Claim are about the ledger LUV and so do not oversell, and "the source's determinacy hypothesis is T1.2 by construction" hints at the specialisation; but [STANDARDS](../../STANDARDS.md) §3 asks the Fidelity line to say *weaker: how*. Fix: `Fidelity: variant: plain trader class — …; weaker: stated at the ledger LUV family (the source's Z̄ is any e.c. Γ_H-determined family)`. Better (and the same proof): ship the general form — `(Z : ℕ → LUV) (hZ : MachineThresholdCodeSeq Z) (z : ℕ → ℚ) (hz01 : ∀ n, 0 ≤ z n ∧ z n ≤ 1) (hdet : ∀ n, LUV.DeterminedVia (Z n) DP (z n))` in place of T1.3/`hmem`/T1.2 — and derive `readability_ofApprox` from it. The general form is exactly what a dependent holding a `CrossQuotePackage` wants (`reflected` is its `hdet`, `quote_codes` its `hZ`): `𝔼^A_n(Y n) ≈ₙ truth n` from a generable approximant of the truth. That is the natural consumer, and it is not in the package.

2. **"A convergent table needs no `hL`" is stated in five places but proved only for a table converging to a *rational* limit.** `li-quote-lane-open.txt` ("non-convergent (a convergent table is priced at its values with no hypothesis: `readability_ofTendsto`)"), the OPEN's docstring (`Readability.lean:307`, "A convergent table cannot be the witness (`readability_ofTendsto`)"), `Readability.lean:46` and `:283` ("a convergent table cannot witness what `hL` buys"), findings F2 ("asymptotically approximable by a generable sequence — which a convergent table always is") and the report's lines 161 and 174. `readability_ofTendsto` takes `L : ℚ`; for a rational table converging to an irrational `L` no constant rational approximant exists, so neither `readability_ofTendsto` nor (as stated) `readability_ofApprox` applies, and a table converging to an irrational that is not even poly-time computable is not excluded as the OPEN's witness by anything the package proves. **The claim is nevertheless true over FAF**, by a route the package does not use: FAF's ε-forms `PolySequence.affine_provind_theory_le_const` / `_ge_const` at `c := L` give `𝔼^P_n(α_{j,n}) → L` directly from T1.2 with no approximant. Probe `FidelityR3TendstoReal.lean` proves `readability_ofTendsto_real (… ) (L : ℝ) (hlim : Tendsto (fun n => (a j n : ℝ)) atTop (𝓝 L)) : (fun n => (ledgerLuv j n).expect P n) ≈ₙ (fun n => (a j n : ℝ))` — `readability_ofTendsto`'s exact conclusion with a real limit — by `readability_ofApprox`'s own route minus the constant coordinate (`As n := expectAffine (n+1)`, bound `1`, value within `1/(n+1) + |a_n − L|` of `L`, then `≲ₙ L` and `≳ₙ L`, `asympEq_iff_asympLE_asympGE`). Fix (either): qualify "convergent" as "convergent to a rational" in the five places and in the open reason; or adopt the probe as the new `readability_ofTendsto` (strictly stronger; the rational-`L` statement is its instance) and leave the wording. The second also makes the OPEN's reason exact: its witness must be a table with *no* limit at all.

3. **F2's "over FAF, L4 needs (L)'s counterpart exactly when the table is *not* asymptotically approximable by a generable sequence" (and the report's line 174) is not what is proved, and as worded it is circular** — when the table has no generable approximant, `hL` fails too, so nothing "needs" it; what the package proves is one direction (an approximant suffices). The sharp, provable statement is an *equivalence* for any reader whose estimates of the ledger LUV are rational — every LIA, by `liaHistory_eq_quote_cast` and the definition of `expectApprox`: **L4 holds iff some `P`-generable sequence asymptotically approximates the table**, because the reader's own estimate `𝔼^P_n(α_{j,n})` is itself `P`-generable (`ledgerFeature`, T4.2, through `PGenerableWeighting.toGeneratedRatFeature`).
