## 3. Non-blocking issues

**N1 — `Twin.twin_kills_good` is universal over `(b, c, δ)`, but in the regime `b(1-δ) < c` its conclusion holds with no twin at all; the name describes the complementary regime only.** The statement: for every `P : Params`, `∃ ρ ∈ [0,1)`, with `s := 1`, the trap is a twin fixed point, the good point is not, `w_island = (1-δ)(1-ρ) < c/b`, `TB` at the trap, the trap a floored fixed point. The proof picks `ρ = 1 - c/(2b(1-δ))` when `c ≤ 2b(1-δ)` and `ρ = 0` otherwise. Probe `TwinKillsRegime.lean`: at `s = 1`, `ρ = 0`, the good point is a twin fixed point **iff** `c ≤ b(1-δ)` (`good_twinFP_noTwin_iff`, from `good_twinFP_iff`); so whenever `b(1-δ) < c` the good point is already dead without a twin and every twin-mentioning conjunct of the theorem holds at `ρ = 0` (`twin_kills_good_without_twin`: trap a twin FP, good not, `w = (1-δ)(1-0)`, `(1-δ)(1-0) < c/b`). In that regime the theorem adds nothing to Theorem A's `δ`-free trap at `s = 1`; "the twin kills the good point" is the content only when `c ≤ b(1-δ)`, where the good point *is* a twin fixed point at `ρ = 0` and the chosen `ρ` removes it (`twin_needed`). The N+ witness `Twin.witness` (`b = 1, c = 1/2, δ = 1/10`) is in the genuine regime (`1/2 ≤ 9/10`, `witness_in_genuine_regime`), so the witness grade stands. The docstring and the ledger's Claim cell state the quantifiers exactly as proved, and the mandate's own target 3(iii) has the same shape (its suggested `ρ > 1 - c/(b(1-δ))` is `ρ > 0` only when `c < b(1-δ)`), which is why this is not blocking. **Fix I'd accept**: either add the conjunct "`IsTwinFP (ρ = 0) good ↔ c ≤ b(1-δ)`" to the statement (so the theorem itself says where the twin does the killing — my `twin_needed` is that statement for the regime), or add one docstring sentence: "for `c > b(1-δ)` the good point is already not a fixed point at `s = 1`, `ρ = 0`; the twin is needed exactly when `c ≤ b(1-δ)`, which is where `Twin.witness` sits".

**N2 — D1's ledger witness does not separate D1 from D0; the mandate's `sos` check does, and it is now a probe.** The D1 row's Witness cell is `BestOnPath.piB_on_chain` (repair round 1): on the trap chain `π^B` is trusted at the root and loses exactly `1 - (1-δ')^K` against the bound `1 - (1-δ)^K`. That is a genuine N+ for the *bound* (neither `0` nor slack). But on the chain `π^B = π^R` at every decision node (`TrapChain.piB_stay`, `TrapChain.piR_stay`, both in `ChainCorollaries.lean`), so no theorem in the package exhibits a model on which D1's policy differs from D0's, or on which D0's policy violates the bound D1 proves for `π^B` — i.e. nothing shows D1 is more than D0 plus a bound that `π^R` would also satisfy. F-19 records the `sos` half as "still not done (not a doubt about D1)". Probe `PiBOnSos.lean` does it: on `sos P`, `B(water) = b`, `S(island, jump) = b(1-δs)`, `S(island, stay) = c`, `val(island, jump) = b`, `val(island, stay) = c`; `jump` is feasible iff `c ≤ b(1-δs)` (the good point's condition, `feasible_island_1_iff`) and `stay` iff `b(1-s) ≤ c` (the trap's, `feasible_island_0_iff`); hence `B(island) = b` and `choice(island) = jump` whenever `c ≤ b(1-δs)`, so **`π^B` is the good point there** (`piB_sos_is_good`, every `P` in the regime). At `witParams` (`b = 1, c = 1/2, δ = 1/4, s = 3/4`): `π^B` jumps, `π^R` stays (`piR_sos_is_trap`), `gap(π^B, island) = 0` (via `Vpi_piB_onPath` and `B_island`), `gap(π^R, island) = 1/2`, and D1's root bound `ε₀ = 1 - (1-δ)^(T-1) = 1/4` — D0's fixed point violates D1's bound by a factor of two, D1's meets it with `gap = 0` (`separation`). Grade: the chain witness is N+ for tightness and N− for separation; the `sos` probe is N+ for separation. **Fix I'd accept**: adopt `piB_sos_is_good` and `separation` (or the regime-general `B_island`/`choice_island`) into `ChainCorollaries.lean` or a sibling, name them in the D1 row's Witness cell next to `piB_on_chain`, and close F-19 (its remaining half is then done). The probe's `rival_eq_other` (on `Fin 2`, `rival(h, a)` is the other action's `Alt`) and `S_water`/`val_water` are the only infrastructure it needs; note that `rival`'s `erase` carries `Classical.propDecidable` because `rival` is defined over a generic `A`, so a consumer on `Fin 2` must pass that instance to `Finset.mem_erase` explicitly (the probe shows how).
