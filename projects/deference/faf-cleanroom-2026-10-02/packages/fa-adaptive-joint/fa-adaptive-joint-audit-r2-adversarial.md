## 3. Non-blocking issues

**N1. T4's witness does not inhabit the OPEN statement's full package; it can, and the probe does it.** `AdaptiveBridgeHolds H f X` quantifies over `G` with `PGenerableWeighting G`, `OnePosition f (G·denote H)` **and** `DivergentWeighting G H`. The ledger's witness for the OPEN `adaptiveBridge` is `onePosition_positive_everywhere` (`Witnesses.lean`), which states: `∃ u, OnePosition (linearSchedule 0) u ∧ (∀ n, 0 < u n) ∧ ∀ d, ¬ (∀ n, u n ≠ 0 → ∃ k, d.f k = n)` — one-position, positive everywhere, on no schedule. It does not state divergence, and a one-position weighting positive on every day can be summable (`u n = 2^{−n−1}`), in which case it is outside the scope of *both* `AdaptiveBridgeHolds` and `hSideBridge` and shows nothing about the former generalizing the latter. So the ledger row's "so T4 is not `hSideBridge`", the report's State (4) ("shows the OPEN object is not the dependency's") and § T4 rest on an inference the Lean does not make. The inference is nevertheless *true*: `audit-r2-probes/WitnessDivergence.lean` proves `u34_not_summable` for the same sequence (`fireSeq (2n+2) 1 (const ¾)`; if it were summable its open mass would be bounded by a tail sum and tend to `0` — the bound inside T2's proof — so the firing value would tend to `½`), hence `adaptFire34_full_package (V : History)`: `adaptFire (const ¾) (linearSchedule 0) 1` is a `PGenerableWeighting` (T1) that on **every** market is one-position, `DivergentWeighting`, and supported on no `DeferralFunction`'s image. That is the witness the row should cite. **Fix:** import the probe's statement into `Witnesses.lean` (or add the divergence conjunct to `onePosition_positive_everywhere` and a feature-level corollary), and point the `adaptiveBridge` row's Witness cell at it. The mandate's own T5 (iii) asked only for "a `OnePosition` weighting that is not schedule-supported", which is what was delivered; the gap is between the mandate's wording and STANDARDS §3's "full hypothesis package".

**N2. The T7 (iii) ledger row's Fidelity claim is false: the uniform no-jump bound is not weaker than `|h_n − h_{n−1}| → 0`; the two are incomparable.** Repair round 1, following audit r1 fidelity N11, wrote into the `v3Theorem2_stale_of_noJumps_of_bridge` row: "the no-jump (c) is the uniform bound `h_n ≤ h_{n−1} + ε/2` on the stale support — a *weaker* hypothesis than the mandate's `|h_n − h_{n−1}| → 0`". The Lean's `hjump` is `∀ n, 0 < staleViol … n → (X n).expect H n ≤ (X (n−1)).expect H (n−1) + ε/2` — on **every** day of the stale support — while `→ 0` bounds only the tail; neither implies the other. `audit-r2-probes/StaleJumpScope.lean` (`hjump_not_implied_by_tendsto`): `a ≡ 1`, `h = 0, 1, 1, 1, …`, `t = ½`, `ε = ¼`, `δ = ⅛` has `|h_n − h_{n−1}| → 0` (it is `0` from day `2`), the stale gate equal to `1` on day `1`, and `h_1 = 1 > h_0 + ε/2`. The theorem itself is fine and its (c) is disclosed; only the comparison is wrong. The reason the Lean needs `∀ n` is that `v3Theorem2_gate_of_bridge`'s `hsupp` is `∀ n` (its proof applies `le_weightedAverage_of_support` to the whole prefix); the mandate's eventual form would need either an eventual-support version of the gate-general theorem (the finitely many early days contribute a bounded amount against a divergent `prefixSum`, so the average is eventually `≥ c/2` — a natural strengthening, not built) or a finite-modification lemma for `LegibleOn`. **Fix:** change the Fidelity text to "the uniform bound `ε/2` on every day of the stale support — incomparable with the mandate's `→ 0` (uniform in size, but on all days, not eventually)"; optionally state the eventual-support strengthening as a follow-up.
