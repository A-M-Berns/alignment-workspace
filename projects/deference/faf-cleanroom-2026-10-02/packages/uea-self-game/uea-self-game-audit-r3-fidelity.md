## 3. Non-blocking issues

1. **"The mandate's iff holds only when `w/(w+θ) < 1 − δ`" (`T3Family.TB_succ_iff`'s Fidelity line; findings F19; echoed in ledger row 27's Fidelity cell) is imprecise.** What is true: the mandate's "`TB_{s_i} ⟺ g ≤ cap`" has `TB_succ_of_cap` as its "if" direction unconditionally, and its "only if" direction can fail *only* when the deviation's own conditional clears the threshold, `(1−δ)(w+θ) ≤ w`, *and* `g > cap` (I recomputed `TB_succ_iff`: `cond_succ_one = w/(w+θ)`, so `thr ≤ cond_succ_one ⟺ (1−δ)(w+θ) ≤ w`). In particular the mandate's biconditional holds whenever `g ≤ cap`, and under the fixed-point condition it always holds (`IsPureFP ⇒ cond_succ_zero ≥ w/(w+θ)`, so if the second disjunct holds then `thr ≤ cond_succ_zero`, i.e. `g ≤ cap`) — which is the context in which the mandate lists the three "exact conditions" together. The docstring's "under the fixed-point condition the second is subsumed" states this but no theorem carries it; `TB_succ_of_cap` is only the "if" direction. Fix: reword to "the mandate's `⟹` direction can fail only when `(1−δ)(w+θ) ≤ w` (and then only for `g > cap`); under the fixed-point condition the mandate's iff is exact", and, if cheap, land the two-line lemma `isPureFP → TB t.succ → g ≤ cap` so that the subsumption is machine-checked. Wording, not a false claim: F19's substantive point (the mandate's sentence, read standalone, omits a disjunct) stands.
2. **F19's "the limit exists, but `θ` must be coupled to `n`" overstates slightly.** The mandate's error is the *order* of its iterated limit ("`θ → 0`, then `n → ∞`"): at fixed `n`, `w/(w+θ) = (1−θ)/(1 + (n−2)θ) → 1` as `θ → 0` and the fixed-point condition fails (F19's computation, which I confirmed). The reverse order works without coupling: at fixed `θ` and `n → ∞`, `w → 0`, `w/(w+θ) → 0 ≤ 1−δ`, the deviation cap tends to `δ + δ²(1−θ)/(1−δ)` (below the `s₀` cap, which equals that value exactly), and then `θ → 0` gives `δ/(1−δ)`. The Lean's coupling `θ = 1/(N+1)` is one valid route and the cleanest to formalize; F19 should say "the order of limits is wrong; `n → ∞` first (or a coupling such as `θ = 1/(N+1)`) works". Precision in a findings entry about the mandate, not about a note.
3. **F17's "Every N+ witness of the package (T1, T2, T3, `√8801`, `Section5`, `FlooredFamily`) sits in the content region"** is loose for T1 and T2, which are stated for every `δ ∈ (0,1)` and so also range over the trivial region `δ ≥ 1/2` (their fixed-point and trust-bound facts remain real there; only Theorem C's conclusion becomes automatic). Say "T1/T2 at `δ < 1/2`, and the four fixed-`δ` witnesses at `δ = 1/10` or `δ ≤ 1/4`". Presentation.
4. **The "exact, unattained supremum" sentence could name both of the note's classes.** `sup_limit`'s docstring states the supremum over "pure fixed points with the trust bound at every situation"; `theoremC_strict`'s upper half holds for the larger class with the trust bound at *some* situation; since `sup_limit`'s instances lie in the smaller class, the supremum is `δ/(1−δ)` on `δ ≤ 1/2` for **both** classes — exactly the two the §5.5 conjecture distinguishes (and conjectured different values for: `δ/(1−δ+δ²)` and `δ`). The fact is implied by the two theorems but not said; one sentence in F1 and ledger row 26 would close the conjecture's two halves explicitly. Presentation.
5. **Report header.** "State of the package" now stacks four state paragraphs (round 0, repair 1, repair 2, continuation); a reader has to reach the fourth for the current state (24 modules, two OPEN statements). Collapsing to one current-state paragraph plus a one-line history would help. Presentation only; every claim in the four paragraphs is consistent with the Lean as it stands.
