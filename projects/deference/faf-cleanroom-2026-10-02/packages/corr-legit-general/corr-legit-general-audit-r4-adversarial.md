## 3. Non-blocking issues

**N1 — The report's "the pair-line system is complete" (T4(d) history section, "Why the search missed it", l. 112: "one linear constraint per closed half-plane class of the finitely many type points; the pair-line system is complete") is false when the type points are all collinear, and the round-3 LP is then under-constrained.** The claim comes from audit r3 adversarial B1 and the docstring of `audit-r3-probes/t4d_lp_search.py` ("one per extreme ray of each half-plane class"). For a class `K` of types the constraint is linear in `(x, s)` and must hold on the closed cone `C_K = {⟨p_t, x⟩ − s ≥ 0 (t ∈ K), ≤ 0 (t ∉ K)}`, so the extreme rays of `C_K` suffice; modulo the trivial direction `(𝟙, 1)` the cone lives in `ℝ³`, and when the normals `(p_t, −1)` span `ℝ³` (types not all collinear) every extreme ray has two independent tight types — a pair line, as the script generates. When all types are collinear the normals span a plane, every `C_K` has a lineality direction, and its extreme rays (in the quotient) are **single-type-tight** lines transverse to the common line, which the pair enumeration never produces. Evidence: `t4d_immodest_search.seed1.out` (the run before my collinearity guard): three types on the edge `p(0) = 0` — cell 0 with no mass, a two-cell question in disguise where `weakValuesWrt_questionOf_of_simpleTrustOn` *proves* weak Value — reported "slack `−2.51`", because the only constraints generated were the pair line's `±(2δ, −δ, −δ)`, which force `m[·, 0] = 0` and nothing else. Consequences: **none for the Lean** — `F7_totalTrustWrt` quantifies over every `X` and `s` and the round-3 certificate's independent integer-direction check does not use the pair system; **none in the dangerous direction for the repair-round-3 numerical probes** — an under-constrained LP can only report *false violations*, never miss true ones, and `t4d_three_types.py` found none (its Dirichlet-random triples are almost surely non-collinear anyway), while the `t4d_vertices.py` vertex was dense-checked independently. Fix: add "for type points not all collinear" to the report sentence and to the script's docstring, and a rank guard (`rank [p_t, 1] = 3`) to `t4d_lp_search.py` and `t4d_three_types.py`, as `audit-r4-probes/t4d_immodest_search.py` now has. Presentation in the report; a correctness caveat for anyone reusing the scripts.
