## 2. Blocking issues

### B1 — `ExactAsymptoticClause` is labelled `Fidelity: exact (the source's clause in the choice reading)` and F14 says the source's sentence is "false as choice"; what the Lean refutes is the `ε_n → 0` reshaping along sequences whose home-value gaps vanish — under the source's own threshold quantifier the choice reading is true on a fixed prior

**Where the claim is made.** `EpsCorr.lean` ll. 198–202 (`ExactAsymptoticClause`): "Source: bli-soto-b-046 ('eventually be optimal in that environment', read as *choice*) … Fidelity: exact (the source's clause in the choice reading, finite horizon; the value reading is `eventually_eps_updateful`)". [udt-bli-learning-findings](udt-bli-learning-findings.md) F14 heading: "holds as *value* and fails as *choice* … (refuted in the choice reading; …)"; body: "**The exact clause without a gap condition is false** … So 'performance … eventually optimal' is **true as value** and **false as choice**". Ledger row 64 Status: "**refuted (finite horizon, choice reading)**". Report state header: "the package's one OPEN refuted"; T9 Status: "**refuted** (unconditional exact form, choice reading)".

**What the source says** (Notion l. 368, re-read): "for each environment, there is some epsilon such that if the agent's belief in acausal correlations is below epsilon, and the environment doesn't systematically introduce such correlations, then the performance of UDT will eventually be optimal in that environment." The quantifier is a **threshold `ε` chosen after the environment**. The package itself records this (the Fidelity line of `eventually_eps_updateful`, F14's "the source's quantifier is a *threshold* …, which the finite form carries and the `ε_n → 0` form reshapes") — for the *value* reading. For the *choice* reading it does not, and there the reshaping is load-bearing.

**What the Lean proves.** `ExactAsymptoticClause 𝒮 m 𝒟 A K` quantifies over *every* `Q : ℕ → FiniteBLIPrior …` (the utility `U` included — the prior's stakes may change with `n`), with `ε_n → 0`, and asks for eventual exact updateful optimality. `not_exactAsymptoticClause` refutes it with `xPrior n = vPrior (1/(2(n+1))) (1/(n+1))`: the home-value gap `g_n = 1/(2(n+1))` and the cross-branch stake `b_n = 1/(n+1)` both tend to `0` (`|U| → 0` uniformly) with `g_n < b_n` at every `n`, so `pay` stays one-step-optimal and never updateful-optimal, while the loss `g_n → 0`. Correct, and honestly described in F14's body. But it is a refutation of a statement **stronger** than the source's: (i) the environment is not held fixed — `xPrior n` is a sequence of environments with vanishing stakes, where the source's "for each environment" fixes one; (ii) the threshold `ε` is replaced by `ε_n → 0`. Refuting a strengthening does not refute the clause.

**What is true under the source's own quantifier.** Fix the environment — a `FiniteBLIPrior P` with two actions — and a table `T`. Either the two home values at `T` coincide (then every action is updateful and any `ε` works), or they differ by `g > 0`, the minimal gap; with `ε := g ρ / (2C)` the finite form `eps_corr_implies_eps_updateful` bounds the loss by `g/2 < g`, so every one-step choice is an updateful choice **exactly**. Probe `audit-r3-probes/FixedPriorThreshold.lean` (elaborates with `scripts/lean-check`, exit 0):

```
theorem fixed_prior_threshold (P : FiniteBLIPrior 𝒮 m 𝒟 Bool) (T : ↥𝒟) (M ρ : ℚ)
    (hM : 0 ≤ M) (hρ : 0 < ρ) (hpol : ∀ c, 0 < P.ppMass T c) (hU : ∀ ω, |P.U ω| ≤ M)
    (hρa : ∀ a, P.IsOneStepChoice T a → ρ ≤ P.branchProb T T a) :
    ∃ ε : ℚ, 0 < ε ∧
      (CorrBounded P T ε → ∀ a, P.IsOneStepChoice T a → P.IsUpdatefulChoice T a)
```

So "for each environment there is some epsilon such that if the belief in correlations is below epsilon then the choice is updateful-optimal" is **true** in the finite shadow (the two-action case suffices for the single-coin and two-table carriers; finitely many actions give the same argument with the minimal positive gap). The choice reading fails only along a **sequence** of priors whose home-value gaps tend to `0` — which the package already states positively as `eventually_updateful_of_gap` ("exact under a uniform home-value gap", "the gap is not removable"). The honest summary is therefore three-way: true for a fixed prior (threshold form); true along any sequence with a uniform positive home-value gap; false along sequences whose gaps vanish (where the choice becomes asymptotically irrelevant by the agent's own lights, and in the refuting family the stakes themselves vanish). "False as choice", unqualified, is the third clause presented as the verdict on the source's sentence.

**Why blocking.** [STANDARDS](../../STANDARDS.md) §3 ("Names and docstrings don't oversell"), §5 ("when it is ill-posed, formalize the nearest well-posed versions and say which the note needs"); audit.md's list ("a false claim in the findings file"). The Fidelity line "exact (the source's clause in the choice reading)" is false of the proposition: it is a *variant* (threshold → `ε_n → 0`; fixed environment → arbitrary sequence of priors, stakes included; "in that environment" → by `Q_n`'s own lights, already disclosed). F14's "false as choice" and the ledger/report "refuted (… choice reading)" inherit the oversell. This is exactly the shape of round 2's B1 (a headline compression outrunning the theorem), one round later, on the item that round's repair pushed further.

**Fix I would accept** (text, plus one optional lemma; no change to any existing Lean statement).
1. `ExactAsymptoticClause`'s Fidelity → "variant: the source's threshold quantifier ('for each environment, there is some epsilon') reshaped as `ε_n → 0` over an arbitrary belief-state sequence (the stakes `U` may vary with `n`, and in the refuting family they vanish); 'in that environment' rendered by `Q_n`'s own home values; choice reading". Same clause in `not_exactAsymptoticClause`'s docstring ("refutation of the reshaped clause").
2. F14 heading and body: replace "fails as *choice*" / "**false as choice**" by the three-way statement above, and add the fixed-prior fact: under the source's own quantifier the choice reading holds on every fixed finite prior (adopt `fixed_prior_threshold` into `EpsCorr.lean`, Kind L, as the Lean form of the threshold sentence — optional but one-liner, the probe is ready), so the refutation needs *both* the reshaping and vanishing home-value gaps.
3. Ledger row 64 Status → "refuted (finite horizon, choice reading of the `ε_n → 0` reshaping, along a sequence whose home-value gaps vanish; the source's threshold form on a fixed prior holds in the choice reading, `fixed_prior_threshold`)"; report state header and T9 Status likewise ("the former OPEN statement refuted" is fine — it *was* the mandate's `ε_n → 0` statement — but "the source's clause in the choice reading" is not).

## 3. Non-blocking issues

**N1.
