## 3. Non-blocking issues

1. **`Chain.dyadic_ratio_bracket`'s docstring and the ledger's `theoremC_depth` witness cell draw a conclusion the theorem does not give.** The theorem proves `gap/bound ∈ (m/(4(m+2)), m/(2(m+2)))` for `m ≥ 2` (correct; I checked the algebra `bound = O₀(m+2)` and the `(1/2, 1)` term bounds). The docstring continues "**So** the ratio `gap/bound` lies in `(1/4, 1/2)` only from `m = 4` on", and the ledger cell says "`Chain.dyadic_ratio_bracket`, so inside `(1/4, 1/2)` only from `m = 4`". This does not follow: the bracket's lower end `m/(4(m+2))` is below `1/4` for *every* `m` (probe `probe_bracket_lower_lt_quarter`), so the bracket never places the ratio above `1/4`; what it proves is `ratio < 1/2` for all `m ≥ 2` and a lower bound tending to `1/4` from below. That the ratio *is* above `1/4` at `m = 4` (`0.2718`) is a separate numeric fact — now machine-checked from the library's own `dyadic4_gap`/`dyadic4_bound` (probe `probe_dyadic4_ratio_gt_quarter`: `bound/4 < gap`); for `m ≥ 5` "from `m = 4` on" rests on the round-2 adversarial auditor's decimals (`0.303, 0.328, …, 0.385`), which are right (the ratio is `≈ (m − 0.76)/(2(m+2))`, increasing to `1/2`) but not in the Lean. The round-2 fidelity audit's §3.1 had the same non-sequitur ("which is inside `(1/4, 1/2)` only from `m = 4`") and the repair copied it. The N+ grade of the chain witness is unaffected — it rests on `dyadic4_informative` (`0 < gap < bound < 1`), which is sound. Fix I'd accept: reword the docstring and the cell to "the bracket gives `ratio < 1/2` for all `m ≥ 2` and `ratio > m/(4(m+2))`; `ratio > 1/4` holds from `m = 4` on (machine-checked at `m = 4`, `probe_dyadic4_ratio_gt_quarter`; `m ≥ 5` by the slack of the first three terms, `∑_{k<3}(term_k − 1/2) > 1`, not formalized) and fails at `m = 3` (`dyadic3_ratio_lt_quarter`)". A general proof of "from `m = 4` on" is a few lines (the three-term slack), if wanted.

2. **The `w_h = 1` corner is generic, and the package states it as an instance fact.** `gap_eq_odds_attained_at_w_one`'s docstring says that together with `gap_eq_odds_not_attained` it "pins the attainment set of Theorem B's bound exactly to `w_h = 1`", and the `InstW` ledger row says "Theorem B's bound `gap ≤ O_h` is attained exactly at `w_h = 1`". An existential at one instance plus non-attainment at `w_h < 1` gives "attainment ⊆ {`w_h = 1`}, and nonempty" — true under a weak reading, but not "exactly". What is true, and cheap, is the exact statement: at **every** plain fixed point of **every** model, **every** decision node with `w_h = 1` attains `gap = O_h = 0`, and the trust bound is automatic there. Probe `AdvWOneGeneric.lean` proves, over all models: `probe_plain_Vpi_eq_Vstar_of_xins_eq_zero` (a plain fixed point is optimal on a `ξ_{-S}`-null subtree — the plain-agent Step 0, which the library has only for floored fixed points, `Vpi_eq_Vstar_of_xins_eq_zero`, while `gap_le_zero_of_xins_eq_zero` takes `TB` as a hypothesis), `probe_TB_of_wS_eq_one` (`TB` holds at every `w_h = 1` decision node of a plain fixed point), `probe_w_one_attained` (`gap = O_h = 0` there, no `TB` hypothesis) and `probe_gap_eq_odds_iff` (at a plain fixed point, decision node, `0 < w_h`, `TB`: `gap = O_h ↔ w_h = 1`). Instance W is then a fine N+ illustration that such nodes occur in models with a residual, but the theorem is the `iff`. Fix I'd accept: land the four probe theorems in `Strict.lean` (or `TheoremB.lean`), cite the `iff` from the docstring and the ledger row, and keep `InstW` as its witness.
