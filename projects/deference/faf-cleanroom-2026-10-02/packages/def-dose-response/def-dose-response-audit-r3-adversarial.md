## 2. Blocking issues

### B1 — "mesh-exact on every steering day" with `0 < N` is `v ∈ {0, 1}`; F6 and `steeredAdvisor_quote_exact`'s docstring describe the family falsely (`lcm` for `gcd`); the steered rows and the OPEN are undisclosed endpoint statements

**The statements.** `Steering.lean`:

```
theorem dose_graded_destination_steered … (MS : MarketComputation (steeredAdvisor A₀ v N)) …
    (γ : ℚ) (hN : 0 < N) (hmesh : ∀ n < N, ∃ k ≤ n + 1, v = (k : ℚ) / ((n : ℚ) + 1)) :
    limitingBelief (arm base γ N c (quoteStream MS)) protSentence =
      ((1 / 2 + γ * (v - 1 / 2) * realizedDose c N : ℚ) : ℝ)
```

`cross_arm_audit_fires_steered` has the same `hN`/`hmesh`; `Open.lean`'s `twoWay_closure_exists` has `(N : ℕ) (hN : 0 < N) {v : ℚ} (hv01 : 0 ≤ v ∧ v ≤ 1) (hmesh : ∀ n < N, ∃ k ≤ n + 1, v = (k : ℚ) / ((n : ℚ) + 1))`.

**What is wrong.** FAF's day-`n` expectation reads the `n + 1` thresholds `i/(n+1)` (the D4 row; `indicatorOf_expect_eq`), so day `0`'s mesh is `{0, 1}`: `hmesh 0 hN` gives `k ≤ 1` and `v = k/1`. Hence, under `0 < N`, `hmesh ↔ (v = 0 ∨ v = 1)` — the full hypothesis package of the three statements is satisfiable at the two endpoint targets and nowhere else. Two *consecutive* exact days already force it (`v(n+1) = k`, `v(n+2) = k'` give `v = k' − k ∈ ℕ ∩ [0,1]`), so the "exposed-day form of the prefix hypothesis" carried in § Not done escapes the collapse only if exposed steering days are never adjacent.

The package does not draw this consequence anywhere, and twice asserts a different one:

- `def-dose-response-findings.md` F6: "For the committed stream to carry `a_n(u) = v` on every steering day, `v`'s denominator must divide `lcm(1, …, N*)`; otherwise (∗) carries a rounding term" — **false**. `v = ½` has denominator `2 ∣ lcm(1, 2)`, and at `N* = 2` the committed stream's day-`0` entry is `⌈½·1⌉/1 = 1 ≠ ½`. The correct condition is that the denominator divide every `n + 1 ≤ N*`, i.e. `gcd(1, …, N*) = 1`: only `v ∈ {0, 1}`. (The same sentence appears in the T2 paragraph of the report through F6's pointer.)
- `Advisor.lean`, docstring of the headline `steeredAdvisor_quote_exact` (Kind C): "With `v` exact at every mesh `≤ N` (e.g. `v = 0`, `v = 1`, or any `v` whose denominator divides `lcm(1, …, N)`), the committed stream has `a_n(u) = v` on every steering day — the hypothesis of `non_attribution` and T2" — the same false clause.
- The ledger's steered row ("`v` mesh-exact on days `< N`"), the OPEN's row and open-list entry ("`v ∈ [0,1]` mesh-exact on every steering day"), the OPEN's docstring ("a target `v ∈ [0,1]` that is exact at every steering mesh (`v = k/(n+1)` for each `n < N`, which is what D4's steered advisor can deliver exactly …)") and report § T2 ("patched at a mesh-exact `v`") all read as a family. STANDARDS §3: when the Lean is narrower than the note's claim, the name and docstring say so; here the Lean is narrower than the note's "dyadic targets" by everything but the endpoints, and the docstrings say the opposite.

**Evidence.** Probe `audit-r3-probes/MeshExactCollapse.lean` (elaborates, exit 0): `meshExact_all_days_collapse` (`0 < N → hmesh → v = 0 ∨ v = 1`), `meshExact_all_days_iff` (the `↔`: the hypothesis package of the three statements is exactly `v ∈ {0, 1}`), `meshExact_consecutive_collapse` (two consecutive exact days force `v ∈ {0, 1}`), `half_not_meshExact_two` (the `lcm` claim's counterexample: `¬ ∀ n < 2, ∃ k ≤ n + 1, ½ = k/(n+1)`), `steeredAdvisor_half_day_zero` (`quoteStreamR (steeredAdvisor A (1/2) 2) 0 = 1`, from the package's own `steeredAdvisor_quote`).

**Why it matters.** (i) A false claim in the findings file and in a headline docstring. (ii) The three composed statements are weaker than their docstrings, the ledger and the report say — proved (or stated open) for the endpoint targets only. (iii) The finding the note needs is missed: under FAF's mesh, the note's "committed stream has `a_n(u) = v` for `n < N*`" (§6.2) is exactly deliverable only at `v ∈ {0, 1}`; for any other target, dyadic or not, the arm reads the day-dependent rounding `⌈v(n+1)⌉/(n+1)` (F6's ceiling), the testimony becomes the exposed-day mean of those roundings, and (∗) gives `½ + γ·(m̄ − ½)` with `m̄` depending on *which* days were exposed — not `½ + s·p̂_i` with one slope `s`. So T2(a)'s dose-graded linear law for the steered-advisor stream holds at the endpoints only; off them the destinations still differ across arms (the audit still fires) but are not graded by `p̂` alone. The witnesses (`v = 1`) are inside the regime, which is why nothing in the package is false as proved.

**Fix I would accept.** (1) A lemma in `Advisor.lean` (the probe's `meshExact_all_days_iff` will do) and one clause in the docstrings of `steeredAdvisor_quote_exact`, `dose_graded_destination_steered`, `cross_arm_audit_fires_steered` and `twoWay_closure_exists`: "with `0 < N` the mesh-exact targets are exactly `v = 0` and `v = 1`". (2) The ledger rows (the Advisor bundle row, the steered row, the OPEN row), the open-list entry, report § T2 and § State say the same. (3) F6 corrected — `gcd`, not `lcm`; the collapse; the design consequence above — and its severity raised from "imprecision" to a local error of the note's §2.1/§6.2 under FAF's mesh (the dyadic-target remark and the exact prescription are incompatible from day `0`), with the honest neighbour named: either confine *exposure* on the steering window to days `n` with `(n+1)·v ∈ ℕ` (the exposed-day prefix form of § Not done, which by `meshExact_consecutive_collapse` must keep exposed steering days non-adjacent) or state T2(a) for the rounded prefix (destination `½ + γ(m̄ − ½)`, `m̄` the exposed-day mean of `⌈v(n+1)⌉/(n+1)`). (4) Re-run the gate if any Lean changes.
