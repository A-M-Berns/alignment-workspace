## F9 — Under `H_unif` the one-level precommitment test is inert: on `segmentSist` every positive-mass policy has `NoStrictPrecommit`, so the tiling separation of `udt-bli-tiling`'s `MuggingTiles` (one-step tiles, updateful does not) cannot be reproduced over the inductor through this policy law (finding about `bli-program` §3.9 U9/U16 and the mandate's T7 (a); analysis of the committed definitions, **not machine-checked** — the Lean is not built, budget; the statement to prove is written out)

**Pointer.** Mandate T7 (a) ("the one-step policy has `NoStrictPrecommit` and the updateful policy fails it (mirror `MuggingTiles.oneStep_tiles`/`updateful_not_tiles`)"); `udt-bli-tiling`'s `NoStrictPrecommitAt P π T := 0 < policyMass π ∧ ∀ b, 0 < policyMass (update π T b) → exAnteValue (update π T b) ≤ exAnteValue π`; `udt-bli-sist`'s `unifLaw 𝒜 := pushLaw (unifMk 𝒜) unifG`, `unifMk 𝒜 (a, π₀) T := if 𝒜 T then a else π₀ T`, `skelU ω π := skelPay ω (π (skelRef ω))`, `skelRef ω := if askC (state ω) then state ω else Qh`; `IndepData.policyMass_toPrior : policyMass π = ν π`.

**The argument.** (i) A policy has positive `unifLaw` mass only if it is constant on the Ask class (`exists_of_pushLaw_pos`: it is some `unifMk (a, π₀)`). (ii) The day-`(n+1)` grid has more than one Ask-class table (any two distinct grid tables with coin `1`, e.g. `sliceT n` and the constant-`1` table), so for a positive-mass `π` and an Ask-class `T`, `update π T b` with `b ≠ π T` is not constant on the Ask class and has `policyMass = 0`: the precommitment clause at an Ask table is **vacuous**. (iii) For a non-Ask `T`, the utility reads the policy only at `skelRef ω`, which is always an Ask-class table (the state itself when it is Ask, else `Qh = askTable`), so `update π T b` and `π` give the same utility on every world, and `unifLaw` gives them the same mass (the off-class law `prodLaw halfW` is uniform); hence `exAnteValue (update π T b) = exAnteValue π` and the clause holds **with equality**. So `NoStrictPrecommit P π` holds for every positive-mass `π` — the one-step policy and the updateful policy alike — and the analogue of `updateful_not_tiles` is **false** on `segmentSist` (and, by the same argument, on `TentSist.tP`): the one-level test does not separate the rules here. The separation in `MuggingTiles` lives on `muggingPrior`, whose policy law has `IndependentPoints`; under `H_unif` ("the 100 % correlated picture", acknowledged unrealistic by its author, udt-bli-sist's `HUnif` docstring) the only deviation the test can see is a correlated one, which is not a one-point update.

**What this says about U16's "fairness and coordination as consequences of faith".** On this witness none of the policy-level structure follows from faith: `Reflective` holds because the prior is `IndepData.toPrior` (state ⊥ policy law), `IndependentPoints` fails on the Ask class (two Ask tables have perfectly correlated points under `unifLaw`, `massOf_unifLaw_pair_in`), and `NoStrictPrecommit` is a property of `unifLaw` plus the utility's reference structure. The honest answer the mandate anticipated ("none follows from faith; they follow from the policy law") is the one this analysis gives. Severity: imprecision in the program's U16 sentence as a target for *this* witness; a `stretch` item recorded, not built. The statement to prove: `∀ π, 0 < (segmentSist …).policyMass π → NoStrictPrecommit (segmentSist …) π`, with the two-table Ask-class witness and the `skelRef` invariance as the two lemmas.
