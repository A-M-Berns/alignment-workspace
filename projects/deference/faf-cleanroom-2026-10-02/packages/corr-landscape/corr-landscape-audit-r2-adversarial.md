## 3. Non-blocking issues

N1. **`Legitimizing`: a second overlap, undisclosed — the delegitimizing instance is inert.** `delegitimizing_instance`'s verdict `φ e s = if s then 3/4 else 1/2` is a function of `S` alone, hence `inert` by the package's definition (`∃ g, ∀ e s, φ e s = g s`); and it is not `legitimizing` about `𝟙[E]` (under the uniform law `E ⟂ S`, so the verdict-conditional mean is `1/2 = E[X]` on both fibers and the quadratic score stays at `1/4`). Probe `LegitOverlap2.lean` (`probe_delegit_is_inert`, `probe_delegit_not_legitimizing`). So the three shipped instances are {inert}, {legitimizing}, {inert ∧ delegitimizing}: two of the three are inert, and the overlap is not only the one F-22 names (inert ∧ legitimizing) but also inert ∧ delegitimizing. The source (S11(a), l. 71: "an event is *legitimizing* …, *delegitimizing* …, **or** inert") means the three as exclusive values of one relation; as formalized they are three independent predicates on three different axes (`σ(S)`-measurability; informativeness about `X`; calibration as a forecast). The ledger row "one `E × S` instance of each class" is true but should say that the delegitimizing instance is also inert, and F-22 should record the second overlap. (T9 is stretch; the finding is already "the classes overlap", so this sharpens rather than overturns it.) A related presentation point: `legitimizing μ φ X` is equivalent to "`V` carries information about `X`" (`condMean ≠ E[X]` on some positive-mass fiber), by the conditional-variance decomposition — the quadratic-score framing hides that every informative verdict is "legitimizing" under the unconditional baseline; worth one sentence in the docstring.

N2. **`Control.CtrlDefined` is a per-state guard; the "undefined under pre-emption" cell depends on it, and the mandate's wording is the marginal guard.** Mandate T10: "`Ctrl` is a `Prop` on the *event* `P(Pr = 1) > 0 ∧ P(Pr = 0) > 0`". The Lean: `∀ i, 0 < infoMass μ i → 0 < pressMassAt μ i ∧ 0 < silentMassAt μ i`. Under the mandate's literal (marginal) guard, `preLaw` (`Pr = I` a.s., each branch mass `1/2`) *is* defined and the develop's value is `1`; probe `CtrlGuard.lean` (`probe_preemption_defined_under_marginal_guard`). The per-state guard is the *right* one — `approval-final.md` D8(i) is `P_t(δ_t(𝓘_t ∨ {Pr_t=1}) ≠ δ_t(𝓘_t ∨ {Pr_t=0}))`, conditioning on the information σ-algebra jointly with the press, and A12.3 quotes the develop's "on the events where each conditioning is non-null" — so the Lean follows the source against the mandate's paraphrase, correctly. But neither the report's T10 paragraph nor the ledger row says that this deviation from the mandate's wording is deliberate and source-driven, and the cell's verdict lives exactly there. One sentence in the docstring of `CtrlDefined` ("per information state, as D8(i)'s `𝓘_t ∨ {Pr_t = ·}`; the marginal guard would make pre-emption defined with value `1`") would close it.

N3. **The drifting-target pair uses a constant disturbance *sequence*.** `traj_outside_drift`/`trajD9_enters_drift` take `Δ* ≡ −σ` (constant) and `ξ ≡ 0`. STANDARDS §3's N+ clause says "not constant sequences".
