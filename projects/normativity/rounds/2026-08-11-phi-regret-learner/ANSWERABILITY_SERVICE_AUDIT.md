# Answerability and service audit

## Result

The action interface integrates; the learning computation does not yet have an
architectural home.

## Answerability of chosen responses

For each fixture at `T=96`, a deterministic-seed sample from every exact rational
mixed action is decoded through the item-29 occasion-local bijection. The
resulting `ActualHistory` passes:

- repository well-formedness and the frozen-boundary check;
- identity replay faithfulness;
- canonical-response encoding;
- absence of ledger drops or retargets;
- obligation closes addressed only to the current occasion's declared burden;
- replay feasibility under the existing disposition work costs.

The learner never changes prior responses. It appends an ordinary current
response, so no retroactive record rewrite is required. These are exact-test-
supported finite integration witnesses, not a general answerability theorem.

## Reasons-responsiveness boundary

The learner uses charge vectors to change its probability distribution. That is
the learning objective, not a legality certificate. Comparator admission still
runs through the nine immutable declarative records and restricted public reason
context from item 29. The learner code cannot add or filter comparators after
seeing profit, and the finite non-capture audit remains empty.

No claim is made that low regret itself makes an action lawful. The actual action
set consists of canonical repository responses; the independent legality of a
counterfactual repair remains the comparator-side predicate.

## Service result

Every selected disposition costs at most the existing per-date response budget.
The weight update creates no docket obligation and does not consume response
capacity in the current model.

That last fact is not a successful bounded-computation result. `ServiceCosts`
has only `per_date_work`, `merits_work`, `default_work`, and `decline_work`.
It cannot express:

- maintenance of 72 positive real-valued weights;
- construction of an 8×8 transition matrix;
- support-graph decomposition and exact stationary-system solves;
- persistence of the learner state as an answerable historical artifact.

Consequently, the implementation would have to treat the theorem computation as
free meta-computation. The intended synthesis requires declared service work,
so the round records integration as blocked.

## Exact next interface debt

A future task should define a learner-state transition record and either:

1. extend the service model with a declared computation budget/cost sufficient
   for the 72 updates and stationary selection; or
2. prove an abstract oracle interface whose use is explicitly outside, rather
   than silently inside, the bounded service claim.

Acceptance requires replayable learner-state evolution, no rewriting of prior
policy states, and an explicit theorem or executable check that each round fits
the declared work model. It need not change the lawful comparator language.
