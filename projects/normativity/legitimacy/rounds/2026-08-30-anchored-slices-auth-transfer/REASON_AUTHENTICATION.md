# Reason authentication

A minimal Answerability Transfer for a reason occurrence \(r\) authenticates:

- source/provenance identity or a valid provenance transport;
- semantic content and target claim;
- unresolved answerability status;
- answer-mode semantics, or a domain proof that the new mode answers the same
  anchored terms.

The one-parent/one-child judgment \(\Translate(r,r')\) is therefore an instance
of authenticated Transfer. Split reasons use a jointly complete target family;
merged reasons authenticate every parent slice separately.

Changing an answer mode from “supply evidence” to “record acknowledgment” is
not a translation merely because the proposition text remains unchanged.

## Deliberate separation from Progress

Reason Carry for answerability asks whether the inherited reason can still
receive the answer it was owed. Cross-era Progress additionally needs a stable
correction/comparison structure: what counts as improvement, comparison
surface, direction, margin, and evaluator transport. A reason translation may
preserve answerability while failing those stronger comparability conditions.

Generic Transfer therefore does not import Progress. Its authentication schema
is independently useful and strictly weaker.
