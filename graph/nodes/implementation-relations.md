## Statement
A notion of one structure implementing another represents objects that move
between variables without letting arbitrary computation make every structure
implement every other.

## Source
projects/deference/note-dump-2026-08-11/notes/roadmap.md, Stage 4, lists the
cluster as related ("causal implementation, triviality, degree-based
recovery"). The problem is stated from its content: causal implementation by
merging variable values and clustering variables is too rigid to handle objects
that move between variables, while general manipulations threaten to make
every structure implement every other.

## Notes
A mid-level plan of Stage 4, filed as an or over three candidate notions:
implementation by degree (simpler translations weighted more), implementation
through condensed descriptions, and a restricted class of translations. The
diagnostic questions of the cluster (the moving-objects argument, the
triviality results, the boundary question) are given parents of the candidates,
and the definitional, comparative and reading tasks are given parents of those.
